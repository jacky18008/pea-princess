# 用量浪費、品質波動與停止紀錄

這輪找到了可以修正的工具浪費，但**沒有證明額外操作指引能穩定省 token**。Astra 的小型有效對照沒有觀察到關鍵品質退步，改善組反而多用 17.7%。Luna 的幾次結果出現硬條件、保存狀態與執行邊界失敗，因此停止擴跑，不能宣稱跨模型品質已受控制。

共執行 **7 次模型 CLI 呼叫，2,775,759 已知 processed tokens**；沒有重試、沒有使用 Claude。原矩陣的兩個剩餘 ID 與後續驗收的一個 ID 均取消，合計沒有超過本輪八次呼叫、300 萬已知 tokens 的操作界線。這不是七次 provider HTTP request 的計數，也不包含 root／評估 subagent 的用量。

## 修正與採用決定

1. **短收據保留。** `session_state.py apply --receipt-only` 只回傳 revision/hash 等識別，不反覆印完整狀態；預設行為不變，批次後仍必須讀完整 context。相同七項條件的離線例子，stdout 從 5,519 降至 183 bytes，減少 **96.7%**；狀態與 journal 的同等結果另有測試。這是輸出大小，不是模型 token 節省率。
2. **補齊正確 API。** `state-api.md` 連到獨立的 [來源操作小抄](../../skills/vet-flat/references/state-sources-api.md)。`document.add` 是頂層 `path`／`line_ranges`，不是巢狀 `document`；`fact.record` 保留精確引文，`output.record` 登錄輸出，不等於語義驗證或任務完成。例子有實際離線執行、錯誤引文及快照保留測試。
3. **隔離驗證失敗，已禁止派送。** 關閉 skill 探索不是檔案隔離。候選 macOS 最小權限設定仍允許共用暫存目錄讀寫，因此 `isolate_workspace_reads: true` 現在會在模型啟動前明確報錯。保留候選設定與離線重現供修復驗證，不啟用不完整的保護。一般執行模式維持原行為。
4. **額外指引不全面套用。** 這次 guided 提醒模型先讀小抄、批次操作與局部查碼，但成本沒有穩定改善。保留可用的工具及文件修正，不將這段組合指引宣傳成無損省 token 配方。

## 方法與版本

[原先固定計畫](plan.md) 是 2 個模型 × 2 組 × 2 次重複，固定 low effort。兩組有完全相同的虛構資料與新版套件，只差額外操作指引；第二次交換組別順序。案例把舊比較與待辦、更新後的帳單、預算／通勤放寬，以及只限 C 的乾燥例外放在一起。模型實際使用工具、改狀態與寫檔。

這是作者編寫歷史後的一次續接；不是模型真的跑完九輪、自然使用者回應、原生 compaction、三種研究深度或高推理強度的驗證。每格兩次仍很少，沒有統計等效檢定。

原計畫在 p05 的外部讀取與品質失敗後停止。p06 在檢查 p05 前已派送，保留結果；p07、p08 取消。隨後固定 [獨立驗收計畫](isolation-canary-plan.md)，最多用原額度剩下的兩次，加入來源小抄與最小權限；q01 失敗後取消 q02。新驗收不是原 A/B 的替代資料，變更多項也不能獨立歸因。

## 有效 Astra 對照：沒有品質退步，但沒有省

| --- | ---: | ---: | ---: |
| 平均 processed tokens | 332,089.5 | 390,853.5 | **+17.7%** |
| 非快取 input 合計 | 65,491 | 90,677 | +38.5% |
| shell 指令合計 | 20 | 26 | +30.0% |
| shell 回傳字元合計 | 232,177 | 212,201 | **−8.6%** |
| 平均執行時間 | 133.0 秒 | 163.0 秒 | +22.6% |
| 校準後品質分數 | 93.75、93.75 | 93.75、93.75 | 沒有觀察到差異 |
| 關鍵失敗 | 0／2 | 0／2 | 沒有新增 |

按重複次數配對，guided 的 token 差異分別約 **+28.3%、+7.0%**。current 的兩次很接近，guided 波動較大；不能挑較省的一次報告。評分的預定門檻是：無新增關鍵失敗、配對平均下降不超過 5 分、個別下降不超過 10 分、單面向下降不超過 1 級。Astra 在這個案例內通過品質門檻；樣本不足以證明一般性無損。

這也直接說明**字元少不等於 token 少**：guided 回傳字元更少，卻多了工具往返及已計量 tokens。native 記錄沒有逐工具的 provider token 歸因，不能把某段字元硬換算成費用或斷言每個指令造成多少用量。

## 失敗帶來的發現

**p05：讀錯版本可以同時讓成本看似下降、品質崩掉。** 它讀到主機另一份 skill，沒有更新實際 context 的 2250／25，卻說已保存新條件；A 明明 £2410 超過 £2350，仍排第一，TODO 還加入未提供的學生／Housing Hand 假設。這份低用量結果無法作為省 token 證據。

**p06：有正確記憶，不代表正確決策。** 2350／35 已寫入，仍把 43 m² 的 B 列第二選擇，違反 45 m² 硬門檻；乾燥檢查的房間範圍也未完整保存。它把完整 context／checkpoint 放到 `/tmp`，違反本次 workspace-only 政策。

**q01：制度化保存也可能保存錯誤。** 新版比較與最終回答直接稱 B 為「面積例外候選」，使用者根本未授權這個例外。最新 context 數字正確、task 甚至 completed，仍不能證明推薦正確。最終 revision 是 21，checkpoint 仍為 10，最後只用搜尋取回 context 部分欄位。新版本檔案確實由當前 output 指向；明確標成 Earlier 的原檔是歷史，不因保留它們扣分。

q01 的外部 skill 路徑搜尋沒有回傳該 skill 內容，不能說成功讀入舊版本；但它仍有 `/tmp/final-context.json` 寫讀。最初的離線哨兵只證明受測外部路徑被擋，實際模型暴露了覆蓋不足。另有兩筆失敗的 `file_change`；stderr 的三段診斷與其重疊，不加成五次獨立失敗。最終明確記錄 Codex 捷徑路徑無法啟動 sandbox helper。離線已重現，改用 canonical 執行檔可建立／更新工作區檔案，外部及符號連結目標仍被拒絕，沒有新增檔案讀取授權。此修正沒有再跑模型驗收，q01 失敗結論維持。

進一步離線測試確認，安裝的 Codex CLI **0.153.4** 在共用 `/tmp`／`/var/tmp` 仍允許讀寫，包含符號路徑、實際路徑、根目錄拒絕及精確檔案拒絕等設定都無法阻擋。只使用本輪建立的虛構哨兵，測後移除，沒有讀取既存暫存檔。這與[官方權限規則](https://learn.chatgpt.com/docs/permissions)所描述的拒絕設定預期不符，因此將隔離功能標成不支援，直接阻止模型派送。canonical helper 修正只解決工具可用性，不能補足隔離；其候選路徑也隨隔離功能停用，沒有以放寬權限換取成功。

不能把 p05／p06／q01 當成三次乾淨、同條件的模型比較；它們有不同配置或污染。但它們已足以否決本輪候選流程的跨模型品質通過聲明。

## 評估器本身的 review

使用 GPT-6 Astra subagent，先不提供模型、組別與用量。保存全部 user／assistant 進度與最終回覆、共同完整政策、原始來源、實際比較／TODO／context、完整工具紀錄與非 shell 事件。共同 skill 只存一份，避免每個樣本反覆複製及讀相同內容；原始資料仍可回查。工具行為可能暗示組別，不能保證完美盲法。

四面向各 0–4：有依據的正確內容、需求承接與實際保存、自然語言及互動負擔、比較與下一步。root 再核對全部關鍵條件、最新檔案與錯誤來源。完整來源、精確引文、未知與例外均在評估包；沒有把虛構的前文或腳本反應當 CSAT。

- Astra 四份原評為 93.75、93.75、100、93.75。root 質疑其中「合成來源／有條件優先」仍偏制式，評估者在未解盲下用一致標準把語言 4 校準為 3；四份均為 93.75。原始評分保留，校準另存，不是新增獨立樣本，也不是改寫成省用量結論。
- p05、p06 分別 31.25、56.25；q01 為 37.5。這些主觀總分不能抵銷關鍵失敗。
- API 執行錯誤若最終確實修復，不自動扣最終正確性；其成本與恢復過程另列。只有實際來源觀察值時，缺通勤目的地警告不代表必須重新問使用者。
- root 起初把 q01 保留舊檔也列為風險，複核當前 output 路徑與 Earlier 標記後修正；該點不當額外失敗。真正的 B 第一、虛構例外與恢復缺口仍成立。

## 用量與驗證邊界

7 次合計 input **2,739,903**，其中 cached input **2,436,608** 已包含在 input；output **35,856**。相加為 **2,775,759** processed tokens，沒有未知 terminal usage。77 個完成的 shell 指令、600,146 回傳字元；2 個非零 shell exit 及 2 筆失敗的非 shell item 分開計數。開發功能警告另列，不能當成 provider 失敗或自動重試理由。

這不是美元、訂閱扣額或整段任務總用量。root 與評估 subagent 在此 ledger 外；provider 內部請求次數亦不可得。新的停止條件確實取消剩餘呼叫，避免為湊矩陣而繼續跑失敗流程。

## 後續工作

- 目前保持已通過的 Astra 案例作回歸基準；不以這個 n=2 結果宣稱所有研究深度或高 effort 都通過。
- 在下一次大矩陣前，先做每個模型的「硬門檻、最新 state、來源版本、實際工具邊界」小型 gate，失敗不擴跑。
- 若要讓低階模型也可靠，下一個有價值的實驗是讓確定性的數值檢查先產出可考慮／不符門檻清單，再測 agent 是否仍擅自改成備選；保留條件例外與證據範圍，不能只靠多一句禁止。
- 預算應同時看 known input／cached／output、工具往返、失敗及語義驗收。不要只設定輸出字數，也不要為了省 token 關閉狀態失效或證據檢查。
- 新要求會讓引擎保守地把先前任務標成需複核；目前不據此自動重跑歷史模型實驗。更細的失效範圍需要明確的依賴設計，不能只憑自然語言 scope 猜測。
