# 原對照停止後的兩次驗收

原計畫執行六次，累積 2,041,240 已知 processed tokens。p05 讀取了工作區外另一份 skill，實際狀態仍是舊條件且排序錯誤；p06 已在檢視 p05 前派送，雖更新條件，仍把面積不符的 B 列為備選，並寫入工作區外的暫存檔。p07、p08 已取消。原始輸出、污染及錯誤均保留，不以新結果覆蓋。

本頁在新模型派送前固定後續方案。這是錯誤觸發的驗收，不是事後修改原本的實驗組。

- 新目錄、新 ID q01/q02，最多再兩次，兩次都為 Luna / low / guided，同一份虛構續接案例。前後合計最多八次 CLI 呼叫，仍共享 3,000,000 已知 processed tokens 的停止線；不是重設預算。每次最多 300 秒，無自動重試。已知用量達線、未知用量或呼叫失敗後不再派送；最後一次回傳計量可能越線。
- 使用新版狀態來源 API 小抄，以及可選的 macOS 最小檔案權限設定。這兩項一起變更，因此不能獨立歸因省用量，更不能把被污染的 p05 當對照。
- 最小權限允許工作區讀寫、系統最小執行環境，以及唯讀的已驗證 Python 執行目錄／framework；關閉命令網路，限制命令 PATH，明確停用已知宿主 skill。其他 OS／Python 安裝尚未驗證，直接拒絕派送，不回退較寬權限。
- 派送前已用虛構哨兵測試工作區讀寫、外部讀寫與符號連結，以及來源快照、fact、context、verify/checkpoint。這是實測子命令邊界；不宣稱外層 Codex 不能載入任何宿主資訊，也不宣稱覆蓋所有工具或敵對攻擊。
- q01 完成後檢查原訂關鍵品質與實際檔案邊界。關鍵失敗就停止；只有保存通過的 root review 才能執行 q02。獨立 Astra 評估保留原評分，root 複核。可以得到「這次驗收仍失敗」的結論。

品質門檻與來源解讀完全沿用 [原計畫](plan.md)：尤其是硬預算／面積、只限 C 的條件例外、乾燥證據的日期與房間範圍、實際保存狀態及未知噪音／合規。未符門檻的 A、B 不得當作已符合需求的替代候選。全包跨模型穩定性、真實長對話及實際用戶滿意度仍未證明。

新權限使用 `default_permissions` 與具名 filesystem profile，不能與舊 `sandbox_mode` 同時使用。[OpenAI 設定參考](https://learn.chatgpt.com/docs/config-file/config-reference)。實作與實測設定會記錄在每次 native invocation；CLI 接受設定不等於模型品質通過。

執行器：`bench/waste_isolation_canary.py`。`prepare --output <新目錄> --prior <停止的原目錄>` 固定來源與先前 ledger 雜湊；`run-one` 每次只執行一個 ID。資料、共同政策、完整對話、工具紀錄、狀態、評分及失敗均保存於私人目錄。
