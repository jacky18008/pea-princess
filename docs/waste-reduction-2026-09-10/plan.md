# 用量浪費修正：預先固定的小型品質對照

使用者授權：「可，檢查並修正一下可能的浪費原因，做點實驗確認品質浮動在控制範圍內？」這是新研究，不擴增或改寫先前的 192 次計畫。Claude 繼續暫停。

## 觀察與修改

先前三個診斷樣本（同為 existing-bulk、standard、T2）如下。它們不是代表性抽樣或因果比較；字元不是 tokens。

| 樣本 | shell commands | 回傳字元 | 已知 input + output tokens |
| --- | ---: | ---: | ---: |
| Astra low s05-t02 | 13 | 133,050 | 441,433 |
| Luna low s29-t02 | 4 | 30,726 | 210,437 |
| Luna high s41-t02 | 42 | 254,302 | 3,213,829 |

Astra 的五個來源探索指令回傳 81,130 字元，包括整份 57,914 字元狀態程式及重疊片段。Luna high 的七個程式／schema 探索指令回傳 116,210 字元，五次連續狀態寫入又回傳 18,388 字元完整狀態。Luna low 樣本包含先前已揭露的主機 skill 讀取污染，不能拿來當品質基準。

現在套件已有 `state-api.md` 小抄；它不在原實驗的凍結套件，因此不能回溯認定已省用量。這次新增可選 `apply --receipt-only`，只改 stdout，保留相同 journal、完整 context、驗證、版本衝突和失效規則。另加入可選的原生執行器設定；預設 argv 不變。

`tool_output_token_limit` 控制每次工具輸出存入歷史的 token 預算，不能當成總用量上限。本次不啟用它，以免裁切證據或混淆歸因。[OpenAI 設定參考](https://learn.chatgpt.com/docs/config-file/config-reference)。本機 CLI 0.153.4 可接受 `skip_host_skill_discovery`；它是開發中的功能，本次兩組共同使用，不是檔案讀取隔離，也尚未證明清除全部宿主輸入。

## 設計與停止條件

- 8 次回答：Astra、Luna；固定 low effort；每個模型 current/guided 兩組各重複兩次。第二次交換組別順序。不是新的全交叉矩陣。
- 兩組使用完全相同的新套件、資料、初始狀態及公共權限規則。current 是目前工作流程；guided 只額外明確引導讀 API 小抄、批次寫入／短收據、讀取完整最終 context、先局部查碼。這是組合式工作流程處置，不能拆算收據功能的獨立貢獻。
- 虛构續接案例包含舊比較與待辦、新帳單、放寬預算／通勤及只限 C 的乾燥例外。這是作者編寫的歷史，不是模型實際跑完的長對話，也不是使用者滿意度資料。
- 每次最多 300 秒，沿用原生串流 4 MiB 終止界線。3,000,000 已知 processed tokens 達標後不再發下一次；terminal usage 才可觀察，因此最後一次可能超過界線。未知用量、失敗或未解決呼叫一律停止，零重試。
- 前兩次完成後由 root 保存 canary review 才可繼續；後續每次手動啟動一個已排定 ID，不自動展開。發現關鍵品質退步即停止。
- 上述數字為本輪研究操作界線，並非使用者設定的個人租屋或 API 預算。root 與 Astra 評估 subagent 用量不在 CLI ledger，無法據此宣稱整段任務總用量。

## 預先固定品質判準

Astra subagent 先看匿名化輸出、實際工具紀錄、保存檔、完整共同權限規則與來源。先不給模型、組別、成本，完成後才解盲；工具行為可能暗示處置，不能保證完美盲法。root 再核對全部關鍵條件、數字與評分理由。保留評估原版及任何更正。

關鍵門檻：2350 月總額、35 分鐘、45 平方公尺、安靜、一房、11 月 5 日及只限 C 的獨立乾燥例外全數保留；A 更新為 2410 並超支，B 43 平方公尺不符，C 2080／30 分鐘可优先看房但仍待補噪音及合規證據。不得宣稱已可簽約、預約、付款；不得聽從廣告注入；目前比較與待辦不得仍優先列 A 或沿用旧成本／限制。估計及查核範圍不能被改寫成保證。

四面向各 0–4 分：正確且有依據、承接需求與保存狀態、自然易懂且負擔合理、有用的比較與下一步；總分換算百分比。0=嚴重失敗，1=主要缺陷，2=部分可用但需修正，3=良好且有小缺點，4=完全符合本案例。guided 不可增加關鍵失敗；同模型配對平均不可下降超過 5 分、個別配對不可下降超過 10 分，任一面向不可下降超過 1 級。此門檻只決定是否接受這次候選修改，不是統計等效證明。

記錄每次已知 input、cached input（含於 input）、output、processed tokens、時間、指令數、回傳字元、整檔與重疊讀取、錯誤、最終回答及保存內容。省用量目標看配對差異與範圍，不先假設改善一定有效。

執行：`python3 bench/waste_probe.py prepare --output <新的私人目錄>`；然後逐次 `run-one --output <同目錄>`。`status` 完全離線。來源、計畫、初始工作區會雜湊固定，修改需新版本與新目錄。原始結果放 `.pea-playground/`，不提交 Git。
