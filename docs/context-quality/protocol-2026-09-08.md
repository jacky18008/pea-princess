# Preregistered context-quality follow-up · 2026-09-08

The user authorized three follow-up experiments: evidence-dependent analysis,
fixed rental next-turn quality, and an offline deterministic reporting/controller
prototype. This protocol is committed before live answer or judge calls. No Claude
calls are allowed; the original seven Claude confirmations remain paused.

## Scope and evidence

Four new analysis cases and six new rental prefixes are authored synthetic fixtures,
not sampled real customers and not a statistical holdout from a production population.
They were not used in the previous three-report trial. Collaborators author fixtures,
neutral summaries and evidence-linked rubrics before any target output. That setup
uses the current conversation's models; its cost is outside the measured CLI workload
and must not be described as zero-cost summarization. No separate live summarizer is
used. This pilot measures the benefit/cost of consuming those fixed summaries; it does
not measure a production compressor's quality or total production pipeline cost.

Freeze case files, question, documents/history, summary/handoff, rubric, runner,
usage parser, target instructions and this protocol with SHA-256. Rubrics are never
sent to answerers. The source ledger and prepared snapshots are checked before running.
Once outputs exist, do not edit prompts, cases, expected findings or the primary grader
to improve outcomes. Any post-hoc review is a separate named artifact with reasons.

## Experiment 1: supported analysis, 4 × 3 arms

Each case has the same question, neutral aggregate summary and document catalog:

- `full`: receives all source documents at the start.
- `summary`: receives only the summary and catalog; may explicitly abstain.
- `adaptive`: receives the same summary and catalog, and may request up to two
  document IDs in one retrieval round. The runner supplies only those sources, then
  starts one final Codex invocation with the original packet and initial response.

Cases cover a subgroup regression masked by an improving mean, a scorecard/source
contradiction, a rare important omission, and evidence too incomplete to conclude.
Source titles cannot substitute for unread contents. The incomplete-evidence case
allows an adequate answer without retrieval. Essential available evidence must fit
within the two-document retrieval limit; selection errors remain a measured result.
No fabricated padding is added to make `full` artificially expensive.
All four analysis cases challenge an acceptance or verification claim. There is no
clean affirmative-control case, so this pilot cannot estimate false refusal of a
well-supported approval. Detailed finding coverage remains separate from abstention.

Outputs are natural-language analysis inside a consistent JSON envelope: answer,
findings with exact quoted excerpts and document IDs, limitations and next steps.
Adaptive's selection request is recorded but not a final quality outcome unless no
retrieval was requested. Its usage includes both invocations when retrieval occurs.
Arm order rotates across cases. All requests use the same no-native-tools instruction
and sandbox; controlled retrieval is performed by the deterministic runner.

Primary quality dimensions are required-finding coverage, critical omissions,
unsupported material assertions, contradictions, useful next steps and appropriate
uncertainty. Exact quote existence in actually supplied evidence is checked by code;
whether the quote supports the claim is a separate semantic judgment. Honest uncertainty
can lose completeness credit but must not be counted as fabricated confidence.

## Experiment 2: rental next turn, 6 × 2 arms

Six authored histories cover verification/safety (2), useful task completion/user
burden (2), and corrected or conflicting facts (2). `full` receives the complete
history; `compact` receives a neutral handoff preserving decision-relevant known
facts, corrections, constraints and unknowns. Both see the identical final user turn
and exact `dist/prompt-pack/INSTRUCTIONS.md` bytes from the same checkout.

The controlled task is manual-mode next-turn advice from supplied fictional evidence.
The entry instructions reference other skill files, but neither arm can read those
files or use tools here. Do not describe this as the complete tool-enabled skill,
an end-to-end conversation, a legal-accuracy evaluation or actual-user satisfaction.
The fixed entry guidance and experiment constraints are identical across the pair.
No persona simulation, satisfaction helper or ordinary persona runner is invoked.

Output is a useful English natural-language reply in one JSON answer field, matching
the fictional users; both arms have the identical language instruction. Analysis
answers use Traditional Chinese. Quality dimensions
include critical verification boundaries, completed user needs, preservation of
corrections, unsupported claims and repeated/unnecessary requests. Do not hide lower
task completion behind a higher safety score. Pair order alternates across cases.
For R3, code checks one to six explicit list items; for R4, exactly three numbered
items and at most 180 whitespace-separated words in the entire reply. These narrow
format checks complement, rather than replace, the semantic usefulness judgment.

## Judge and offline review

Answer model: `gpt-5.6-terra`, effort `low`. Auxiliary rubric judge:
`gpt-5.6-sol`, effort `low`. These are explicit requested model IDs, not claims about
provider-internal deployment revisions. One judge invocation per case scores all
anonymous candidates against full sources and the frozen rubric: 10 calls maximum.
Candidate labels are deterministically shuffled per case. Arm names, tokens and
selection requests are hidden. Input availability is not a reason to award an
unsupported claim credit; useful abstention is allowed by the rubric.

The judge must provide quoted response support for each criterion and enumerate
unsupported claims/contradictions. It receives no costs or preferred winner. The
criteria R1-F6 and R2-F6 are explicitly conditional accuracy checks: if the response
does not discuss the listed facts, mark them inapplicable and exclude them from the
applicable-criterion denominator. All other required criteria remain applicable.
Omitting an optional affordability aside is not equivalent to missing a critical
payment or access boundary. The individual applicability labels remain inspectable.

Model judges can still have family, position and style bias. Raw judge labels remain intact;
independent source-grounded review of all cases will record disagreements separately.
This is expert-like agent review, not independent human validation. Citation string
checks, rubric coverage and judge annotations are different measures; do not collapse
them into a purported objective product-quality score.

Development methods are informed by [OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices):
task-specific criteria, separately reserved evaluation cases, explicit failure
thresholds and controls for response-order/verbosity bias. This small authored pilot
does not satisfy a claim of population-level equivalence or noninferiority.

## Budget, telemetry and stopping

Maximum: 12 analysis initial calls + 4 possible retrieval follow-ups + 12 rental
answers + 10 judges = **38 Codex CLI invocations**. No additional connectivity canary
is planned; the prior trial already established CLI operation. First measured calls
serve as operational checks and remain in the results. Run sequentially.

Stop starting new calls at **900,000 reported processed tokens**, including judges,
or 38 calls. The token threshold is checked between calls and can be exceeded by the
last in-flight request; it is not a hard spend cap. Each call times out at 180 seconds.
No automatic retries. Provider error, missing terminal usage, malformed events,
unexpected native tools or an interrupted/failed call stops the live runner and
preserves evidence. A malformed retrieval request is recorded as a protocol failure
without granting extra retrieval. Quality failures are findings, never grounds for
rerunning until an answer passes. Finish the preregistered pilot within these limits;
do not expand to additional cases after observing favorable results.

Use the last direct `turn.completed.usage` from each independent invocation and retain
input, output, cached input, cache-write input, raw JSONL, command, prompt, schema,
answer, hashes and duration. Processed = input + output; input cache and output
reasoning subdivisions are not added again. Adaptive totals include selection and
retrieved-answer calls. Judge tokens are shown separately and included in overall
experiment cost. Absent usage is unknown, never zero. These are CLI measurements,
not an invoice or subscription allowance. Parent/subagent implementation, fixture
authorship, manual review, reports and offline compute are outside the paired totals.

## Experiment 3: zero-model control prototype

Build an explicit event reducer and about 20 hand-authored event traces with independent
expected states, covering normal, empty/incomplete, duplicate, unknown usage, failed
attempt, first provider failure, late in-flight completion and explicit resume.
Check every prefix as well as final outputs: a pause must block subsequent dispatch,
usage must count known failed work once, and low quality/abandonment cannot trigger
provider retries. Preserve source events and result snapshots. Neither expected data
nor results may invoke a model. This is an offline prototype experiment, not a change
to all production controllers or a measurement of real notification latency.

## Reporting and interpretation

Report every case and arm, retrieval choices, response hashes, quote checks, individual
criterion outcomes, unsupported claims and total tokens. Show cost and quality side
by side; do not select a single aggregate winner that conceals a critical failure.
Full-context answers can be wrong, so they are a comparator, not ground truth.
Use the source evidence and rubric as the reference for all arms.

Adoption is only a pilot-level decision: a candidate with new critical omissions or
unsupported consequential claims needs revision/verification even when it uses fewer
tokens. A successful adaptive answer may cost more than full context due to an extra
invocation. Such outcomes must be reported. Frozen rental handoff preservation does
not prove arbitrary automatic compression is safe. Additional untouched cases and
human review would be needed before broader product claims.
