# 給 ChatGPT（Pro，請用最深的推理模式）的審閱提示

**附件**：`review-bundle.md`（一個 Markdown 檔，內含一個開源 agent skill「Pea Princess／vet-flat」的全部公開文件：模型指令、參考細則、資料源清單、實驗結果、安裝說明）。請先完整讀完附件再回答。

## 背景（兩段就好）
這是一個給任何 AI agent 用的「倫敦租房盡職調查」技能：用英國官方與公開資料（能源證書 EPC、警方犯罪 API、Companies House、倫敦市府規劃資料庫、TfL、Land Registry 開放資料等）對一間出租公寓做 12 軸檢查，產出白話判決報告（PASS／EDGE／CONDITIONAL／KILL），每個發現標證據等級。設計原則：任何模型、任何 agent 都能用（Claude、Codex、Gemini、Grok、開源 agent）；事實由腳本抓取、模型只做判斷；不爬取條款禁止自動存取的網站，改請使用者貼頁面；報告以 JSON schema 為準、版面由固定產生器輸出；報告裡每個數字必須附來源或算式（validator 強制）；算術一律用 `calc.py`；預設配置「便宜模型做抽取、最強模型做判斷」，並有自動升級階梯。

作者做了一輪 A/B 與消融實驗（附件內 EXPERIMENTS.md）：5 戶真實房源、人工覆核的雷點答案卷、各種 harness 配置在 Claude 與 Codex 上各跑 5 到 10 次。主要結果：事實層各配置差不多（約 0.65 到 0.75）；雷點召回率差很大——「每軸一個子代理讀原始網頁」0.87 但每戶 $31 且兩成失敗，「腳本骨幹＋最強模型判斷」0.57 每戶 $6.7，便宜配置 0.15 到 0.38 且會捏造數字；Codex 側 GPT-5.6 Sol 走腳本路線雷點召回 0.30，最小模型 Luna 用 standard 模式反而 0.46。答案卷偏向「讀原始網頁」的做法，這是已知偏誤。

## 請你做七件事（每件獨立成節，先講結論再講理由）
1. **架構與發布決策批判**：廠商中立的做法、JSON schema 優先、腳本 vs 原始網頁、自動升級階梯、「無來源不印數字」、預算模式。哪些是對的、哪些會在真實使用時出問題、你會怎麼改。
2. **實驗設計挑毛病**：樣本數、雜訊處理、答案卷偏誤、決策規則、把「判斷品質」量化的方法。給一個你認為更站得住的實驗協議（含成本估計）。
3. **事實核對（英國法規與資料源）**：附件裡所有法律與數字斷言（Renters' Rights Act 2025 生效日與內容、押金與訂金上限、預付租金上限、90 晚規則、熱網監理、EPC 規則等）逐條核對，**每條附一手來源連結**；資料源清單裡有沒有漏掉重要的官方或公開來源；有沒有已過時或錯誤的端點描述。
4. **非工程師體驗**：讀「這能幹嘛」的短講、六題問法、十條入門常識、安裝說明。從一個完全沒概念、只用 ChatGPT 免費版或 Plus 的人的角度，哪裡會卡住、哪裡會誤解、哪裡該砍。
5. **風險審查**：網站條款（只列名字不給抓法是否足夠）、使用者上傳文件的隱私、報告點名房東或建物的誹謗風險、授權選擇（文件 CC BY 4.0、程式 MIT）、署名機制、被整包抄走時的實務對策。
6. **給 OpenAI 模型的具體建議**：以你對 GPT-5.6 系列的了解，哪些提示與 harness 調整能讓它在「判斷層」（找雷點、寫關鍵問題）表現更好；Codex 沙盒與額度的注意事項；小模型在 standard 模式勝過大模型在 lite 模式，這現象你怎麼解釋。
7. **發布前十大優先改進**：排序、各附工作量估計與預期效果。
