## Token 暴增的原因

- 64 場實際使用的都是 **`claude-opus-5`，不是文件寫的 Sonnet**；未指定模型使 CLI
  沿用昂貴的預設值。兩輪包含 487 個已保存受測 agent 回合，不是 64 次單輪呼叫。
- 控制主對話每次輸入上下文中位 **531,375 tokens**；335 次監控事件反覆喚醒它。
  這份主對話還包含其他工作，不能把整份消耗全算成本專案。
- 原報表漏掉 persona、滿意度與 judge helpers，且早期失敗重試與 timeout 用量不完整。
  這兩輪 helpers 在 Codex，不能把它們的消耗加到 Claude 頭上。
- 獨立 benchmark 紀錄的 processed tokens 約 **8.07 億，93.74% 是 cache read**。
  這是重複處理文字的總量，不是新生成量、帳單，也不能直接換算成週額度百分比。
  DNS 出錯是最後七場作廢的原因，不足以解釋整週用量暴增。

[完整用量審查與官方來源](2026-09-08-token-audit.md) 把實驗、混合主對話、
cache、估價與訂閱額度分开，並附去重方法與逐場模型身分證據。
