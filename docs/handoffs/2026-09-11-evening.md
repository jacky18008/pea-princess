## Context slimming — plan only, nothing started (author: design the experiment first, version everything)

Where the tokens go: every tool call re-sends the whole context (system prompt, skill text, conversation,
every earlier tool result); standard depth adds 15–25 calls per flat, and each big tool result is re-sent
on every later call (one 80k-character planning dump was re-sent ~30 times ≈ 0.8M tokens). Caching is
already good (Claude 88–92%, Codex 87–97%), so the levers are calls and result size, not the prefix.

What the vendors say (from their documentation, from memory; verify the pages before quoting):
Anthropic prompt caching (stable prefix first, volatile last); Anthropic context engineering for agents
(smallest high-signal set; just-in-time retrieval; structured notes in files so the conversation can be
compacted; sub-agents that return summaries); Anthropic context editing (clear used tool results);
Claude Code (sub-agent output stays out of the main context; short CLAUDE.md; compaction with
summaries); Agent Skills spec (SKILL.md < 500 lines, references on demand); OpenAI Responses caching
(instructions and examples first, user data last, stable order); Codex (short AGENTS.md with a byte cap,
reasoning effort, web-search context size low, sub-agents).

Three places with room, none of them the skill text:
1. **Tool results**: scripts return a fixed summary; the raw records stay in files (`area_scan.py` is the
   pattern). Candidates: planning (stages/officer report), EPC certificate, company profile/filings,
   reviews digest. Expected: standard per flat from ~1.5–2.5M toward ~0.3M ●.
2. **Old conversation**: the ledger file (`.pea-state`, profile) is written before compaction; the
   checkpoint rule becomes "ledger file first, conversation second".
3. **How the model reads files**: "read the one section the route names", not `sed -n '1,240p'` dumps.

Do not touch: the skill text (already small; cutting it cuts rules) and the host system prompt.
Sub-agents for isolated reading: theoretical gain, but the role-pipeline ablation (2026-09-07) found no
quality gain at 2–4× cost — only with a measured experiment.

### Experiment design (before any change ships)

- **Bench**: the existing full-vet benchmark (`bench/run.py`, `bench/grade.py`, private gold, the same
  5 flats) for quality and tokens, plus the private-corpus replay (15 cases, judge v2 pinned to Opus 5,
  no profile prior) for conversation quality, plus the programmatic checks (numbers without cue,
  questions, jargon).
- **Arms**: baseline (frozen tag) · A = per-axis summary scripts behind flags · B = A + ledger-first
  compaction rule · C = A + read-the-section instruction. Change one thing per arm.
- **Cells**: models Sonnet 5 and Codex terra · depths lite and standard · 2 repeats per cell (paired
  by flat and by case; report paired differences; n stays small — direction, not rates).
- **Metrics**: landmine recall/precision, fact recall, fabrications per run, verdict match, unknown
  axes; tokens per run split into fresh input, cache read, output; tool calls; wall time; replay v2
  gates, T dims, first sentence, satisfy, vs-original.
- **Gate to adopt**: no quality metric worse than the baseline's run-to-run noise (use main vs main-2
  as the noise estimate) and tokens at least 30% lower; otherwise the arm is recorded and dropped.
- **Version control**: tag the baseline (`git tag baseline-context-<date>`); each arm on its own branch
  (`exp/context-slim-a`, `-b`, `-c`) and, for replay runs, a `--skill-dir` snapshot made with
  `git archive` into `bench/ab/skill-variants/skill-<commit>`; every results folder records the commit
  of the skill it ran; scripts change behind flags so the baseline stays reproducible; the judge model
  and prompt are not changed during the experiment; merge only the winning arm, one commit per arm,
  with the numbers in the message and in `docs/EXPERIMENTS.md`.
