# 用新模型／新版重測已保存的對話

在本機測試台選一段已保存的真人對話，按 **用新版重測**。預覽會列出已完成的問答、附件數及原模型。選擇新模型和這次的呼叫／token 上限，按 **建立重測**。建立與預覽均不呼叫模型。

新對話提供兩種執行方式：

- **重測下一輪**：沿用下一輪的原始使用者輸入，取得一則新回答後停下。
- **連續重測**：依序執行剩餘回合，直到完成、你暫停、達到上限或發生錯誤。遇限流、未知用量或失敗不自動重試。

展開 **重測對照** 可以逐輪看原回答與本次回答，也能回到原對話。**檢閱過程** 繼續保留這次的原始回答、工具觀測、呼叫收據與 tokens。中途可以送新問題或附件；會優先回答你的插話，停止自動重測並標記這段已修改。繼續歷史腳本需再次按下一輪或連續重測。

## 保存與執行語意

原對話不會覆寫。新 session 保存來源 ID、來源內容 hash、原版本檔案 hashes、原模型及新模型；新模型使用測試台目前凍結的程式／skill 版本。程式更新後先重啟測試台，再從舊紀錄建立新版重測。這不是任意 Git 版本切換器。介面目前仍是 Codex 三個已提供模型，effort 為 low；本功能未接入 Claude 或 Grok，也未更動它們的暫停狀態。

每轮只把當時使用者已送出的文字和附件放入新回答的上下文。原答案只供檢閱，不交給新模型；後續回合會收到本次新產生的前文。連續的多則使用者訊息若原本由同一則回答處理，重測也會保留為同一組，不憑空增加回答呼叫。

原始文字及附件 metadata 留在私人計畫。建立時驗證並保存所選回合的附件快照，再逐輪交付指定副本；不因文字看起來像路徑就重新讀取本機原檔。缺少或受損的快照會阻止建立／執行，不偷偷使用更新後的檔案。附件延用六份／訊息、25 MiB／檔案、48 個不同 ID，單段重測附件總量最多 512 MiB。尚未完成回答的尾端輸入和排隊訊息不納入，預覽明示數量。第一版支援測試台已保存的真人對話，包含舊版比較模式；合成人物的動態模擬及外部 Claude/Grok 歷史匯入另屬其他工具。

上限沿用 durable controller：每個歷史問答組最多購買一次新回答，不另外呼叫使用者模擬器或評分模型；失敗保留收據。token 門檻在呼叫間檢查，一次進行中的回覆可能超出剩餘 token 額度，不能當作供應商硬性費用上限。完整對話超出 runner 容量就停止，不靜默截短。

## 比較結果的限制

這是固定輸入的回歸測試。原追問如「第二間比較好」可能依賴原回答；新回答順序變了，該追問就可能不再適合。因此建議第一次先逐輪檢閱，再決定連續跑。歷史使用者的滿意／不滿意不能冒充對新回答的即時反饋；加入新的真實回應後會標記 modified。

即時網站內容和工具結果可能改變。附件快照相同不代表所有研究證據相同，也不能將品質或 token 差異全部歸因於模型／prompt。需要控制資料條件的實驗應另外固定證據。原始結果、重測結果、模型用量與評分應分開保存。

所有資料維持 `.pea-playground/` 私人本機儲存；匯出也包含私人內容。來源 hash 是完整性證據，不是加密或同一 OS 使用者的隔離。模型仍透過使用者自己的 Codex 登入處理已交付內容。

## API 與驗證

`GET /api/session/{id}/replay` 只預覽；`POST` 同一路徑接受 `source_sha256`、`model`、`max_calls`、`max_tokens`、`client_id`，建立另一個 session，無模型派送。既有 control 的 `step/run/pause` 處理新計畫。API 沿用 loopback、Host／Origin、自訂 header 及 JSON 邊界。相同操作重送不重複建立；來源改動會拒絕舊預覽；建立中斷的半成品不能被視為完成或開始模型呼叫。

本輪採離線 actor stub 與瀏覽器操作驗證控制流程，沒有新增實際模型呼叫，不把測試通過稱作新模型品質驗收。結果和部署紀錄會另列於本文件的交付紀錄。
