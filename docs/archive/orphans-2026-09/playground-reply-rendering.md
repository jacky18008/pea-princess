# 本機對話的 Markdown 顯示

對話實驗室現在把訊息中的常見 Markdown 呈現為段落、清單、粗體／斜體、行內或區塊程式碼、標題、連結及簡單比較表。這是 `playground/app.js` 的 DOM 顯示修正，沒有改動模型提示、人物設定、原生執行、用量限制或插話流程。

原本直接使用 `textContent` 是安全的，但會把 `**重點**`、清單及表格標記原樣顯示。新的 renderer 使用 `createElement` 與 `textContent` 組合元素，不使用 `innerHTML`，也不把回答交給 HTML parser。原始 HTML 與圖片語法維持可讀文字，不建立圖片或其他會自動載入內容的元素。只有明確的 HTTP／HTTPS Markdown 連結可點擊；新分頁使用 `noopener noreferrer` 及 `no-referrer`。其他協定、相對網址及不支援的連結格式保持原文。

這是有限的 Markdown 子集，不宣稱完整 CommonMark／GFM 相容。巢狀清單可能以較簡單的清單或縮排文字呈現；引用、參照連結及其他未支援語法不刪除。未關閉的程式碼區塊保留原文。過長或超出解析步數的內容退回文字呈現，沒有截斷回答。程式碼不執行，表格只調整閱讀方式。

## 原始紀錄與品質解讀

畫面優先呈現已存在的 `display_text`，沒有時才使用 `text`，與原本選擇方式相同。renderer 不寫回任何訊息，私人匯出、A/B 原始回答、提示、用量、正式封包與評分都維持原樣。

這項修正處理「格式符號直接出現在畫面」的問題，不能證明模型更會對話、問題更少、研究更完整或品質分數提高。模型原本輸出的冗詞、錯誤及刻意跳脫的 Markdown 仍保留；不可將顯示改善記成新的模型品質 A/B 結果。

## 離線驗證

```sh
node --check playground/app.js
node tests/test_playground_ui.js
```

測試執行實際 renderer 與 UI handlers，涵蓋段落／清單／表格、程式碼原文、HTML 與圖片不執行、不安全網址不建立連結、沒有額外網路請求、不支援語法保留、解析限制及訊息物件不變。既有額度上限、非同步回應、插話、固定選項與 idempotency 測試一併保留。驗證不需要模型呼叫或重啟伺服器；既有對話可在重新載入靜態頁面後檢查顯示。
