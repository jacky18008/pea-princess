## 先分清楚測到了什麼

這輪測試使用真正的公開資料與實際測試台，沿用先前整理的私人 Claude 找房歷史 case 05，改編為一條真實街道的四輪對話。原始紀錄、來源行號、UUID、雜湊及改編界線均保留在私人證據中；這是開發用回歸案例，不是新使用者、未見過的 holdout 或使用者滿意度真值。

初始的「臥室早上必須有直射陽光」是本輪測試者新增的條件，不冒充原始歷史使用者要求。安靜自始至終只是一項偏好。流程是：

1. 實際完成道路、鐵路、夜間場所、噪音、規劃施工及生活環境的標準街道研究。
2. 用實際表單的自由文字欄放寬採光，要求沿用研究，其他條件不變。
3. 插問冬季採光、詢問是否改成加分，明說先給建議、不要代為決定。
4. 從模型真正提供的選項中選擇採光只作加分，不捏造選項；提交後檢查下一輪回答。

同一場使用同一個持久化 Lab session；每輪 provider CLI 重新啟動。這不等於測試 Codex 原生長對話續接，也不等於已經有程式驗證的需求、候選排序和待辦。當前 agent 路徑保存的是原始使用者訊息與研究檔。

## 通路、來源與同步

已完成的五場都實際完成自由文字提交及固定選項提交，沒有用普通預寫訊息冒充表單。表單送出的問題前綴、真正選到的文字、後續回答和來源 hash 都保留。

已完成場次的六類研究來源有資料。場內後三輪沿用相同研究 envelope、結果雜湊及保存日期，未觀察到重新搜尋或重掃。B2 第一輪兩次呼叫掃描器，第二次明確讀取已保存結果；「呼叫掃描器兩次」不等於取得兩份新研究。

不能只用 ZIP 相符推定指引有被模型讀到。因此另核對實際 physical request：已完成場次的 prompt 都包含其 assigned conversation-quality 全文，B 的新增段落確實在輸入中。內容存在不等於模型遵守，但排除了這些樣本「新版文字未送入」的解釋。

來源只證明街道／區域層級資料；不能證明臥室朝向、室內安靜、日照、任何特定單位可租，或工程已開工。部分來源有年代及覆蓋限制，沒有把未知補成通過。

## 超時與紀錄缺口

B3 的掃描指令有開始事件，沒有完成事件。保存的 envelope 仍是 running，沒有 result、saved_at 或六類來源覆蓋證據。模型反覆讀同一份 running 紀錄並等待，最後達 300 秒單通期限；沒有最終回答與 terminal usage。等待指令的要求秒數有重疊，不能把它們直接相加當成實際牆鐘時間。

事後檢查 envelope 記錄的 owner PID 已不存在，紀錄卻仍為 running。這是掃描程序的進度／終止狀態與診斷缺口；現有證據不能定位到某一外部來源或斷言外網故障。空的 `gap_count=0` 不代表六類來源成功。

完整失敗收據已保留，coordinator 記錄 usage=null 並阻止後續派送。沒有用另一次成功結果取代這場超時。

## 成本與檢查器

第一場呈現同一段對話中的大幅成本差異：T3 不用工具為 24,385 tokens；T2/T4 分別為 156,963／181,533。差異與重讀文件、保存草稿及檢查流程相符，並非重做外部研究。沒有逐工具 token 計量，不能把全部差額精確分攤給某一工具。

最明顯的離群值是 A2 T2：**435,886 tokens**。該輪先讀約 77,963 字元，再做四次草稿修改與四次 checker；沒有新增研究或模型重試。

另外不能把 checker 的 clean 或儀表板的 failed-tool count 當完整品質保證：

- B1 首輪的後續 checker 呼叫移除了 `--previous`，因此 clean 不能證明先前需要比較前文的問題已修復。
- A2 T2 有 `checker; sed ...` 的組合，前者發現問題，後者 exit 0 掩蓋了工具層的失敗訊號。
- A2 T4 有草稿 patch 格式錯誤的 stderr，但未反映於該輪 failed-tool count。

兩組成本不得只比較成功場次均值後宣布 B 更省或更貴：B3 是未知用量且未完成，缺失不是隨機刪掉的數字。A1/B1 及 A2/B2 的差異方向也不同。這輪不支持成本優劣的穩定因果結論。

## 盲評、覆核與品質結果

由 GPT-6 Astra 子代理使用執行前固定的 rubric 逐輪評估：A 是擅改使用者要求的嚴重度、E 是來源／事實問題、U 是有用推進、Q 是互動負擔、O 是開頭品質。A/E/Q 越低越好，U/O 越高越好；各軸分開設門檻，不能用內容正確或流暢開頭抵銷實質需求錯誤。整段的語意門檻是每輪 A≤1、E≤1、U≥1、Q≤1；開頭另須每輪 O≥1。A2 代表實質條件轉換，A1 代表措辭鬆動但尚未形成實質規則／行動改變。

| 場次 | 盲評 trace | 最嚴重 A/E/Q | 最低 U/O | 本範圍四輪驗收 | 主要原因 |
|---|---|---|---|---|---|
| A1 | 204 | 2/0/0 | 2/2 | 未通過 | T1 把安靜與採光合併成使用者的淘汰條件 |
| A2 | 203 | 2/1/0 | 2/2 | 未通過 | T1 明說安靜與直射陽光是「兩個硬條件」 |
| A3 | 201 | 1/0/0 | 2/2 | 通過 | 有語氣邊界，但未確認實質擅改條件 |
| B1 | 206 | 1/1/0 | 2/2 | 通過 | 局部措辭與來源衍生文字不精確 |
| B2 | 205 | 1/1/0 | 2/2 | 通過 | 局部措辭與來源衍生文字不精確 |
| B3 | 202 | 未評 | 未評 | 執行受阻 | T1 超時，後三輪未執行 |

主要分母保留六場原定樣本：語意、需求權威與本範圍完整驗收皆 **3/6**。僅以完成場次計為 3/5，這是輔助描述，不能把超時刪掉。A 與 B 各三場中沒有一組全部通過；單一改編情境、不同時間的少量重複不足以證明 B 有穩定因果優勢、跨模型效果或品質等效。

所有 20 輪完成回答的 U/O 都是 2，Q 都是 0：在此 rubric 下有具體判斷、能推進，沒有過度追問。不代表使用者會覺得夠精緻、滿意或願意繼續用；本輪沒有新的人類反應標籤，不能從預寫選項與追問推論滿意度。

完整驗收的範圍是這個 Lab agent 路徑的對話、六類有限範圍來源、實際表單往返及研究沿用。**程式核對的標準化需求、候選排序與待辦在這條路徑仍屬 capability_missing，未被本輪驗證。** 也未驗證原生 Codex／Claude／Grok 的對話接續或介面。

原始對話、實際表單輸入與 source JSON 送入匿名分組的評分包；prompt／skill 內容與原始組別映射暫不提供，避免暴露改動條件，原文另外完整保留。盲評不是保證 evaluator 無法從回答風格猜組別；亦沒有重新抓取全部外部來源。最終評分固定後才讀組別映射，`grades.json` SHA-256 為 `e3dda856243b8e819fbef2d0323bbcef67cef4c462290bbff3978842ed149e08`。逐輪公開分數見 [grade-summary.json](grade-summary.json)，原始私人引文及指向留在本機。

開頭可見性另外做了覆核：最初包只有 provider 發出的進度，不能證明使用者看過。補充兩份相同的凍結 renderer／host 程式與五場 CUA 操作證據後，確認此 Lab 執行中顯示的是系統工作中提示，actor 回答在完成時才加入 messages。因此完成回答的第一句就是此通路首次可見的 actor 文字，20 輪皆 O2；provider 進度仍另存，不混入可見開頭評分。補證據只改變 O 的可觀測性與相依驗收結論，A/E/U/Q 原評分完全不變，修訂前草稿也保留。

root 另讀實質問題與邊界回合的完整前後文，同意最終分數，沒有在解盲後改分。特別保留兩個容易過度判錯的例子：

- A1 T4 開頭說不能同時接受昏暗與車流，但後文說的是重新權衡／降低優先序，不能僅憑開頭斷言新淘汰規則。早期過程審查較嚴重的懷疑，經全文覆核採 A1；這不影響該場 T1 已有的 A2。
- A2 T2 把「可接受的通風」寫成使用者放寬採光後仍保留的條件。保留 A2，同時標註這是最接近邊界、可能有評分分歧的一筆；若清楚寫成研究者建議即不成立。即使降為 A1，該場 T1 的明確錯誤仍使整場不通過。

模型提出偏強的建議不是自動錯誤。要分清楚「我建議先看安靜的單位」與「這不符合你已決定的必要條件」，也不能把選項的問題前綴或未選建議當成使用者授權。

| 優先級 | 已觀察問題 | 影響與處理方向 |

## 下一輪應優先針對的機制

以下是根據過程與來源審查提出的待測方向，不是已證明有效的修復：

1. 把使用者原話、選項的實際答案、agent 問題前綴、建議分開保存。需求強度／優先序的更新須有對應使用者證據；不能從模型自己先前的結論取得授權。
2. 移除需求轉換表中的隱含承諾。例如 how-to-use 的「我怕吵」會同時寫入安靜優先於採光與避開朝道路／鐵路窗的條件。這是具體的文件張力，但本輪尚未證明其因果影響，且它也沒有明文說「偏好安靜」必須升為硬條件。
3. 回覆檢查應由程式固定提供參數、分離 exit codes，限制自動修稿次數；checker 過關仍須另過對話品質門檻。不要為修文案每輪重讀大段來源文件。
4. 掃描逐來源保存階段與結果，區分 running、owner 已消失、來源超時與資料缺漏。未知進度不能讓模型反覆睡眠，也不能標成零缺漏。

沒有把短指引版當已驗收修復合回 main。本輪程式新增的是可恢復的測試協調與證據流程，不是已獲品質認證的全套產品。
