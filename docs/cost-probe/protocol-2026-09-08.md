# Preregistered Codex-only cost pilot · 2026-09-08

Question: do the handoff's proposed coordination changes reduce measured model
tokens while preserving the facts and required next action in an experiment report?
The user explicitly authorized a live test with **no Claude calls**. This is a new
Codex experiment; the seven paused Claude rental confirmations remain paused.

## Scope and fixed controls

This replays **saved results**, not rental conversations. The same requested model,
`gpt-5.6-terra`, reasoning effort `low`, output schema, no-tools instruction and
read-only sandbox apply to every arm. There are no persona, satisfaction or judge
model calls: Python grades the factual reporting contract. A successful telemetry
canary used one additional Codex call; it is recorded separately from the comparison.

The source is the verified September 8 rules-only copy of the original, first-fix
and failed second-fix persona scorecards. Preparation records hashes of every source,
background file, packet and schema before the first treatment call. Historical raw
results are never rewritten. The background is the two actual September 6 design
discussions (38 KB); it has no invented padding and is far smaller than the former
controller's 531k-token median context.

## Interventions and order (10 calls maximum)

| Dataset | Verbose callbacks | Compact coordination | Final-pair order |
|---|---|---|---|
| First matrix, 32 results | At 10, 21 and 32 observed sessions | Python keeps intermediate records; one final call | verbose then compact |
| First fix, 32 results | At 10, 21 and 32 observed sessions | Python keeps intermediate records; one final call | compact then verbose |
| Second fix, 7 provider errors | One final failure-triage call | One compact final failure-triage call | compact then verbose |

Verbose calls receive the genuine design background, their own earlier callback
answers, every currently observed raw scorecard row, and Python-computed reporting
facts. Compact calls receive only those **same** computed facts, without a preselected
decision. Both must apply the identical reporting rules. Thus the treatment combines
fewer callbacks and smaller context; it does not force mental arithmetic on the
verbose model or award the compact arm exclusive access to aggregate facts.

The first two datasets test eliminating routine progress notifications. The third
tests preserving null quality and a pause decision on a failed batch; it does not
test live incident-alert latency or suppress the first failure notification. All
low-scoring or abandoned sessions remain valid findings and must not be retried.

Each call is a fresh Codex invocation, with the specified history replayed in its
prompt. This avoids confusing cumulative session counters on resume. It measures a
controlled replay and does not reconstruct the old persistent Claude implementation.
Precomputed facts in both arms are software work, not hidden model summarization
calls. Both have the same no-tools contract. Future callbacks that require inspecting free-form
transcripts may need more evidence than this compact reporting schema.

## Measurement and acceptance

The CLI's raw JSONL, exact command/prompt, final JSON, prompt/event hashes, duration,
input, output, cached-input and cache-write counters are retained for every call.
Use the last `turn.completed.usage` snapshot per independent invocation. Total
processed tokens are **input + output**; cached input, cache writes and reasoning
are subsets, never extra total tokens. The existing parser's reasoning double-count
was fixed before this pilot. Sources: [Codex non-interactive output](https://learn.chatgpt.com/docs/non-interactive-mode),
[prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).

Primary comparison: sum every verbose callback's processed tokens versus every
compact call's processed tokens. Also show final-report pairs and input not from
read cache (`input - cached`, including cache writes); these are token measures,
not bills. A fresh process does not imply a cold provider cache; order is partially
counterbalanced, but caching remains a caveat in this small pilot.

Python checks the exact observation counts, all outcomes, graded/provider split,
safety-cap and safety-miss counts, mean/median, retry IDs and next-action decision.
Only mean/median allow four-decimal rounding (absolute tolerance 0.000051). Provider
failures have null quality, not zero. The final-report goal requires all three
compact reports to pass. Report any baseline or compact error, including intermediate
callback errors; never rerun solely to obtain a better score.

Stop after any failed provider call, absent telemetry, unexpected tool event, or
600,000 reported cumulative tokens. The threshold is checked between calls and is
not a hard per-request cap. Each call times out at 180 seconds. There are no automatic
retries. If stopped, retain the evidence and do not declare a completed comparison.

## Commands and limits of inference

```sh
python3 bench/cost_probe.py prepare --output bench/results/codex-cost-probe-2026-09-08/trial-v1
python3 -u bench/cost_probe.py run --output bench/results/codex-cost-probe-2026-09-08/trial-v1
```

Preparation refuses an existing output folder. A run skips recorded completed cells;
an interrupted or failed cell requires inspection and is never silently overwritten.
All executable model commands are Codex. A tool event invalidates the trial even if
the answer looks good. Results and prompts remain local under ignored `bench/results`;
the protocol, code, tests and final aggregate report are committed.

This pilot cannot establish full rental-agent quality, real-user outcomes, overall
workflow savings, a Claude counterfactual, money saved, or subscription quota savings.
Parent/subagent work building and analyzing the pilot is outside the paired workload;
do not present the paired totals as the entire cost of this task. Canary/setup calls
are reported separately, and process-level raw evidence is retained.
