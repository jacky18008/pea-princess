# Codex-only 實測：監控與交接少用 85.2% tokens

使用同一個 `gpt-5.6-terra`、`low` effort，對三組真實、已保存的 persona
實驗結果進行報告重播。**全程 0 Claude 呼叫**；原本七場 Claude 確認仍維持暫停。
程式先記錄進度，最後只傳必要統計的方式，從 **302,259 降到 44,842 processed
tokens（−85.1644%）**。兩邊的三份最終報告都通過同一套事實檢查。

這是監控與交接這一段的實測，不是重新跑租屋對話，也不是整個專案成本降低 85%。
它不能直接換算成帳單、訂閱額度或 Claude 的節省比例。

## 預先固定的比較

[Protocol](protocol-2026-09-08.md) 在正式模型呼叫前已提交為 `d0a8caa`。
固定模型、effort、工具政策、輸出 schema、source hashes 與 Python 評分規則。
兩邊都拿到**完全相同的程式統計**，都必須自行判斷下一步，沒有把答案的 decision
預先塞進精簡版。舊方式另帶真實設計稿、原始分數表及先前的進度回覆。

兩組 32 場資料的舊方式分別在第 10、21、32 場呼叫模型，新方式只在最後呼叫。
七場失敗資料只比較最後一次故障判讀，沒有延遲第一個錯誤通知的實驗。
最終配對順序有交換；每次是獨立 Codex invocation，按指定內容重播歷史。

| 已保存的結果組 | 舊方式呼叫 | 新方式呼叫 | 舊 tokens | 新 tokens | 減少 |
|---|---:|---:|---:|---:|---:|
| 首輪 32 場 | 3 | 1 | 138,987 | 14,910 | 89.3% |
| 修補後 32 場 | 3 | 1 | 136,293 | 14,916 | 89.1% |
| 7 場連線失敗 | 1 | 1 | 26,979 | 15,016 | 44.3% |
| **合計** | **7** | **3** | **302,259** | **44,842** | **85.2%** |

只比較同樣三份最終報告，把多出來的四次進度回調拿掉，仍是
**139,071 → 44,842（−67.7560%）**。這個次要比較顯示，縮小上下文本身也有差異；
主比較則同時包含縮小上下文與減少回調次數，不能把兩個百分比相加。

## 有沒有漏掉重要判讀

**10/10 份回覆通過；其中三份精簡最終報告全部通過。** Python 直接從來源分數表
重新計算，而非讓另一個模型主觀打分。檢查項目是場次、各種 outcome、有效／provider
error 分流、平均／中位分數、安全線壓分與遺漏次數、可重試的 session IDs、下一步。
均分／中位數只容許四位小數的四捨五入差異，其他欄位要求精確一致。

尤其失敗組，兩邊都正確回報 **graded=0、provider errors=7、品質數字為 null**，
下一步為暫停供應商呼叫，且列出原定七場；沒有把空白輸出當成模型品質差，也沒有
把其他批次的放棄或低分場次列為應重試。三組最終輸入的統計內容也逐一確認相同。

這只驗證報告欄位正確，不代表模型對租屋問題的回答品質、真實使用者滿意度或法律
判斷已經重新驗證。碰到必須閱讀原始對話才能判讀的事件，仍應按需帶入證據。

## 計量與快取

| 計量項目 | 舊方式 | 新方式 |
|---|---:|---:|
| Input | 301,180 | 44,353 |
| Output（已含 reasoning 如有） | 1,079 | 489 |
| Cached input（input 的子集） | 0 | 24,064 |
| Cache-write input（input 的子集） | 0 | 0 |
| Input 未從 read cache 取得 | 301,180 | 20,289 |
| **Processed = input + output** | **302,259** | **44,842** |

原計數器會把 reasoning 額外加入 total，本次已於 `ba94d98` 修正。
每次只取最後一筆 `turn.completed.usage`，不把 cached、cache write 或 reasoning
再加一次。[官方 JSONL 說明](https://learn.chatgpt.com/docs/non-interactive-mode)與
[快取計量](https://developers.openai.com/api/docs/guides/prompt-caching)。

快取表現不同：舊方式沒有觀察到 cache hit，新方式有 24,064。這裡的 **85.2% 是
包括 cached input 在內的 processed tokens**，不是靠把 cached token 當免費才算出來。
但不能據此宣稱費用也降低 85.2%；小樣本、cache warm-up、獨立程序的路由與上下文
差異都限制了金額或額度推論。每次 CLI 原有的指令／工具描述開銷也算在量測內。

## 這次試驗本身花了多少

- 10 次正式呼叫：347,101 CLI processed tokens，合計約 151.125 秒。
- 先行連線／計量 canary：14,040（input 14,031、output 9），約 9.762 秒。
- **已知 CLI 合計：361,141**，包含刻意支付的舊方式對照。
- 以上不包含主對話及協作代理撰寫、審查、分析試驗的用量，不能稱為整個任務的帳單。
- 沒有重試、沒有缺失的正式呼叫用量、沒有工具事件或 Claude 呼叫；沒有為了拿高分補跑。
