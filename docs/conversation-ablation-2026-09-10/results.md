# 原生代理對話消融：最終結果（2026-09-10）

> 原定可執行回答、正式主評分、獨立四段長對話複核及成績揭露後的分歧整理已完成，完整私人備份已實際還原驗證。本篇保留原分數與後續更正的不同證據範圍；失敗與未執行名額沒有改標成功。

本輪檢查把 skill 入口縮短、把文件從全文預載改成按需讀取，能否維持多輪任務品質並降低整段代理工作的用量。結果沒有支持「提示較短就會穩定省 token」或「compact 已無損」的結論。原主評審在本案例給 Astra 較高分；不同入口及讀檔方式的平均差較小，但個案、成本與延伸表現仍有差異，不能據此宣稱一般模型排名或品質等效。

已知用量為 **161,368,696 processed tokens**，另有兩筆逾時用量未知。獨立複核也確認「最後答得對」與「目前接續文件正確」並不相同：四段最後都有可用方向，但兩段仍有過期狀態、待辦或必要文件覆蓋缺口。另確認九次工具回傳工作區外的舊版 skill 本文，正式評分又缺少完整共同權限政策；原高分不能被當成事實真值、安全認證或完全隔離實驗。

## 4. 對話、使用者反應與證據

同一合成租屋案例測試候選比較、預算降低、優先順序、面積必要條件、沒有完全符合候選時的下一步、僅對單一候選生效的例外、插問、來源更正、估計與實測的區別、只放寬特定條件，以及最終可恢復檔案。每格只有一個作者編寫的情境，n=1、沒有獨立重複，也不是未參與開發的保留測試集。

| 證據或機制 | 本輪用途 | 限制 |
|---|---|---|
| 使用者訊息與來源文件 | 按凍結輪次釋出需求、更新及文件 | 不是隨機招募真人，也未涵蓋廣泛情境分布 |
| T2、T7 固定反應 | 依前則回答長度或問號數選預寫分支 | 不是語意理解、真人滿意度或 CSAT |
| 對話與最終回答 | 正式 packet 有逐輪使用者／最終助理正文及反應標記 | 問號不等於決策數；首次有用進展的輪次沒有收集 |
| 工具事件與檔案 | 正式評分可讀已捕捉 trace 及 T3／T9 產物 | 宣稱完成不等於檔案存在；檔案存在也不等於內容正確 |

正式評分有完整情境、rubric、最終回答、工具與 T3／T9 產物，沒有全部獨立進度訊息。補充包也不能單獨提供完整使用者情境及 rubric；長對話複核須把同一 A/B 的正式輸入與補充合讀。交接逐檔核對原付費評分前的實際檔案快照，不把後來資料悄悄當成原主評審已看過的證據。

## 5. 原始正式 AI 品質結果

以下只彙總原來 22 次 Astra／low 成對評分與既有 reducer，不是在撰寫本篇時重新評語意。評審與其中一個被測模型同屬 Astra，尚無足夠獨立人工校準；部分盲評也可能讓評審推測條件。平均分不能視為模型普遍能力排名。

T1–T8 為八個單輪面向，S1–S6 為六個整段面向，每項 0–3 分，未觀察或不適用留 null。診斷指數 Q = `100 × (0.5 × 可評 T 平均 + 0.5 × 可評 S 平均) ÷ 3`，兩層等權；任一層無資料則 Q=null。正式 compact 配對紀錄按區段給分，不能假稱每個進度訊息均有獨立標註。

另有 G1 事實與證據、G2 授權與安全、G3 當前必要條件。原欄位 `safe_task_success` 要求任務 complete 且三項均 pass；partial／failed 或 gate fail 為 false；沒有已知失敗但必要判斷未知則為 null。本篇稱為「**依所供政策計算的完成指標**」，不稱為安全通過率。詳見[評估設計](../conversation-evaluation-design.md)。

### 5.1 G2 的共同權限政策缺口

回答者收到的共同 BOUNDARY 限制工作區、網路、訊息、外部服務及其他模型／代理，並說明來源不是授權。正式 packet 的 capability 摘要與 case／README 沒有完整重現這份政策。G2 要依所供政策判斷，政策不足時應能標 unknown；工具 trace 偶然含相關字句，不保證所有配對取得相同完整政策。

原 G2 在 44 個前綴及 4 個延伸都記為 pass。這是**原主評審輸出，不是共同限制均獲遵守的證明**。本篇不把原分數默默改成 fail 或 unknown；完整政策覆蓋的未知，以及加入精確原政策後的個別違規，另列於第 8 節。三種證據範圍不能壓成一個看似一致的安全數字。

## 6. 成本與初始估算責任

已知 **161,368,696 processed tokens** = input 159,831,793 + output 1,536,903；cached input 146,934,656 已包含在 input，不能再加一次。兩次失敗缺少直接用量，整體總量仍未知。這不是帳單金額或帳戶全部用量；協調、其他對話及後續補充評估沒有同樣收據，未併入。

| 觀察 | 已核對結果 |
|---|---|
| 原生啟動與工具工作 | 186 次 launcher attempts；3,239 個已完成命令；底層 provider request 次數未知 |
| 主要階段 | T3 已知 67.711M，占全部已知小計約 42.0%；原 judge 6.094M，約 3.8% |
| 高耗用尾端 | 最高 20 筆成功回答占回答已知小計約 47.0%；最大單筆 6.246M |
| 模型 × effort 的前綴小計 | Astra low 15.725M、high 25.637M 加一筆未知；Luna low 12.628M、high 94.982M 加一筆未知 |
| 設定一致的事後 entry 成本對照 | bulk 下 12 對 outcome 相較 existing 合併小計 +20.0%；routed 下只有 6 對，+12.4% |

沒有顯示短入口能穩定降低整段用量。大量 input、快取與工具工作可直接觀察；長上下文重讀、API 探索及不同步數是合理機制，但沒有逐工具步驟的 provider usage，不能編造某份文件各耗多少 token。高 cached 比率也不等於處理免費。完整表格與可比子集見[成本分析](costs.md)。

**初始 600 萬估算明顯失準，實作者應負責。** 192 次由完整矩陣、延伸與評審組成，不是收集中臨時增加；但實作者沒有充分估入每次啟動內部的多輪工具／模型工作、累積上下文與評分成本。使用者後續要求先完成原範圍並解除門檻，不會讓原估算變得合理。240 秒也是實作者設定，修正後必須保留不同期限與失敗。

本輪依指示完成收集後才分析浪費，沒有中途換較省的 prompt 或混入新速查表。call、時間與 token 上限是不同控制；只能在 CLI 返回後取得用量的 gate，不是可精確即時截斷的 token hard cap。下一輪需要先用小型試跑確認整段分布，再按明確停止門檻擴大，不能只用「每格一次」估算。

## 9. Insights 與下一輪小型、設門檻的實驗

可以保留的工程結論是：持久化條件、原始需求與來源很必要，但「有保存」與「接手時仍然正確」是兩件事。驗收需要分開看最終答覆、研究文件必要覆蓋、目前條件、待辦與實際授權動作。正確短答不能消除錯誤 resume；文件很完整也不代表使用者每輪都應閱讀整套流程。

目前沒有足夠證據把短入口全面取代既有入口，也沒有測到所有模型／深度都能無損 compact。交付版的功能改善可繼續驗收；任何模型行為推進應另開版本，保留這輪基線、失敗及原評分。下一輪宜先回答小問題，而不是直接再展開同樣規模：

1. **校準評估輸入。** 回答者與評審使用版本固定、完整的共同權限政策；用可核對正反例確認 G2 能區分 pass／fail／unknown。評審先檢查必要覆蓋與目前狀態，不能只追求 JSON 或引文驗證通過。
2. **控制額外輸入。** 建立可驗證的受控 skill 來源並記錄實際發現與讀取。探索開關不等於檔案讀取隔離；未確認輸入範圍前不擴大矩陣。
3. **單獨測已交付的 API 速查表。** 在基線上只加這份文件，用少量預先指定案例及相同工具、模型、effort，記錄接口探索、步數、用量與條件正確性。文件已實作，模型收益仍是假設。
4. **拆開入口兩項改動。** 分別測去重與減少固定程序，保持領域義務、工具及資料相同；加入未參與開發的情境及配對重複，避免把單一腳本結果概括成通用規則。
5. **分開測長期恢復與即時改向。** 真正 resume 須綁定明確、受控的對話 ID；執行中的插問另做測試。兩者都保留取消、重啟、原始訊息、條件範圍、狀態更新與用量證據。
6. **先訂停止門檻再擴大。** 小型跨模型試跑先觀察高耗用尾端，再設每階段用量、工具步數與回傳字元門檻；未知用量和失敗獨立保留。需要更細硬限制時，先補工具攔截或逐步用量觀測，不能把事後檢查冒充即時 token cap。

上述提案未在本輪額外執行，也不是已測出的省 token 比例。腳本反應不是真人 CSAT，AI 評審不是真值；單一合成情境、部分盲評及相同工具，不能提供完整產品或資安保證。
