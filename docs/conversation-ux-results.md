# 合作式租屋對話：修正與實測

2026-09-09。這次修正來自使用者實際否定舊回答的經驗：六題入門問卷、流程術語、內部引用和整段法規說明，讓對話沒有先幫使用者理解或推進選擇。目標是研究助理與決策者持續合作；使用者調整需求，agent 提供研究、比較、解釋與可操作成果。

## 原因與修正

舊測試偏重條件覆蓋、機械流程與接口正確，沒有充分驗收對話品質。入門文件、prompt pack、persona、runner 和本機政策重複施加流程要求，模型照著做仍可能產生很差的體驗。新的行為是先做有用的比較或研究，再以通常零至兩個、最多三個必要問題取得下一步需要的資訊；不是把完整問卷拆成好幾輪。

`5886d26` 修正現行人物話語、skill/文件、報告標籤和本機介面。介面顯示可操作的選項與自填欄位，沒有替使用者預選；選項、原文和插話都進私人紀錄。API adapter 的選項介面是我們自己的實作，不宣稱它就是 Codex/Claude 原生澄清工具。原生 host 支援時，skill 指引使用它實際提供的介面。

`8563b09` 進一步去掉重複缺口盤點，讓開場先提出比較或工作方向，並保護正在執行的伺服器不把舊程式錯標為新版本。舊測試保留可讀、可匯出；不把新的品質判斷附到舊 prompt 上。

## 有界實測

兩份計畫都在呼叫前保存：[六次計畫](conversation-ux-smoke-plan.json)、[一次開場複驗](conversation-ux-refinement-plan.json)。全部使用 gpt-6-astra / low；沒有 Claude 或自動重試。

| 凍結版本／案例 | 呼叫 | processed tokens | 實際觀察 |
|---|---:|---:|---|
| 5886d26 / C1 | 4 | 98,350 | 3 則回答、1 次動態 persona；中途排入的問題在當則完成後優先處理，保留安靜比近車站重要的變更 |
| 5886d26 / C2 | 1 | 26,226 | 兩題；保留費用上限和樓層，例子仍偏制式 |
| 5886d26 / P2 | 1 | 26,090 | 一題；照使用者指示先看合約，最貼近當下需求 |
| 8563b09 / C1 開場複驗 | 1 | 26,433 | 兩段正文＋兩個選項問題；先比較虛構例子，不再開列未知欄位 |
| **合計** | **7** | **177,099** | 6 則 assistant 回答、1 次 persona 模型呼叫 |

前五則回答問題數為 **2、2、0、2、1**。最後一則複驗為 **2**。UI 中實際看到了 radio choices 和自行填寫欄位；離線 JavaScript 檢查覆蓋部分回答、非預選、原樣顯示、重試去重。真人在目前編碼對話中的批評和方向調整另存於私人持久 state；沒有假稱它們是在 lab 發生的對話事件。

最後開場的實際內容先比較「朝庭院但離站較遠」與「近站但朝繁忙街道」，明確標示並非可租房源，給一個噪音檢查，然後說明應比較房租加帳單，最後用校區和預算問題推進。回答比原本有幫助，但仍有精簡空間。沒有真人滿意度複驗，因此不稱為 UX 已通過。

## 品質與能力限制

- 這七次是小型開發實測，不是消融實驗或品質等效證明。評分者知道開發目的，獨立 AI 複核也不是人工真值。
- 本機舊聊天 adapter 沒有真實房源搜尋工具；只能使用所附資料或清楚標示的例子。它不能證明真正 native agent 的研究、工具、檔案產出品質。
- 5886d26 的多輪回答仍多次盤點未知欄位；8563b09 只重測一則開場，不能把改善推及整段長對話、全部16個persona或別的模型。
- 費用估計與實測通勤的區別保留在指引中，但本輪沒有重演 Grok 原本20／24分鐘估計被簡化成勾號的情境；不能宣稱那個實例已驗證修復。
- 1,900 項離線測試在8563b09提交前通過（51.544秒）；它們驗證接口、資料和回歸，不等於模型回答好用。

## Token insight

舊三個糟糕開場用了79,677 tokens，其中 input 分別25,879／25,898／25,900，output 696／740／564。主要成本是每次重送上下文與CLI固定內容，不是回答多了幾句。直接把回覆變短，不能解決大部分用量。

本輪前六次150,666 tokens，單則追加26,433；不是對照相同輸入的成本A/B，不能宣稱省多少。cached input 已包括在 input，不能再加一次。這些是終端提供的 processed counters，不等於訂閱額度百分比或 API 帳單；編碼、協作代理和外部 Grok 用量不在此表。

[文章審查](article-harness-review.md)發現固定載入38,977字元的指引，再追加政策與歷史；因此下一步比較指示與資料載入方式，而不是單純限制輸出長度。

## 後續驗收

完整方法與分數面向：[對話評估設計](conversation-evaluation-design.md)。接續的 native-agent study 另凍結48組 model × effort ×研究深度×入口×資料載入組合，包含四段較長對話、資料更正、條件例外與檔案恢復。這份報告的七次紀錄不能代替尚未產出的新矩陣結果。

私人的 `ux-smoke-20260909/` 和 `ux-refinement-20260909/` 保存計畫、intent IDs、source commit、snapshots、完整匯出及逐筆用量；每個session底下保留durable manifest和物理終端原文。原始使用者內容不自動公開。操作方式見[本機介面指南](persona-playground.md)，Grok模型選擇的官方說明見[來源說明](grok-model-selection.md)。
