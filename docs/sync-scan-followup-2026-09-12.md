## 程式與實機驗證

獨立暫存 repo 的三代服務測試已核對公開來源、ZIP、載入檔案完全一致。持有實際呼叫鎖時舊 PID 不變，釋放後才換版。故意引入錯誤 Python 原始碼後，舊頁面可讀、新呼叫被拒絕；還原後恢復可用。全程零模型呼叫，歷史 manifest 不變。

實機測試發現舊 HTTP 連線的 TIME_WAIT 會被 plain bind 誤判成連接埠占用，已修正 preflight 的 socket 重用設定，並加入真實 socket 回歸測試。檢查仍拒絕其他正在監聽的程序，不按連接埠殺程序。

多輪模型驗收採預先登記的四輪上限：Terra、standard、low，同一對話用原來兩份 PDF，接著掃描兩條街、插問與收緊房租上限、續問。原計畫第四輪包含重啟，但在第四輪前發現同版重啟相容性缺陷，已先登記修訂，保持原版本完成第四輪；不能宣稱原四輪通過了重啟。800k processed tokens 是呼叫之間的停止門檻，單次可能超出；不自動重試、不使用 Claude。後續輸入由測試者 Agent 撰寫，不計入真人滿意度。

### 第二段修復驗證

另行預登記最多兩次 Terra / standard / low，700k processed tokens 於呼叫間檢查、每次 300 秒、不自動重試、不用 Claude。版本是 `73bab5a` 的公開 ZIP `c92d722ed89c7a5c31d22eb126362bf553cfa2762210145ae2710e7bfaabbd46`。使用相同兩份 PDF，第一輪合併欄位比較、兩街研究及一個原生問題。

**第一輪完成後因正確性問題停止，第二輪沒有 dispatch。** 不是耗盡用量上限，也不是控制器中斷。第一輪 448,683 processed tokens（442,767 input，其中 380,416 cached；5,916 output），139.10 秒、10 次工具操作，其中 3 次失敗。獨立 Astra 的結論是 **blocking correctness**，原評分與原始輸出都保留。

留下四份封套：N6、W6 被送入完整郵遞區號 endpoint 的兩次定位失敗，以及後來兩次取得部分資料的 standard 掃描。這不是四次完整重複掃描。但模型後來複製腳本示例座標、使用未提供來源的座標；雖然最終配到真實街名，選點仍不夠可靠。它也把近道路時的靜態提醒說成「地圖顯示有安靜一側」，並再次將使用者偏好升格成必要條件。既有用途合法證明又因含 basement 被選成施工調查線索。

這段實測將責任定位到**公開腳本的輸入與解讀契約，加上模型的條件擴張**；當時公開來源、ZIP、actor 的 102 份檔案一致，不能歸因於測試台沒同步。

隨後做了真正的同版本 stop/start：已完成的對話、manifest、snapshot、四份研究封套、相容性與呼叫數全部保持一致。獨立 Astra 另行重算 session 與封套雜湊。這證明已完成研究能跨重啟保存；**未提交原生選項來產生下一個模型回答，因此仍未證明完整「選項提交 → 續答」流程。**

第一段加第二段共 **5 次測試模型呼叫、1,243,119 processed tokens**。不含開發與評閱 Agent 的用量。輸入合併方式、程式版本、定位和掃描取樣都不同，不能拿兩段差異宣稱省了多少 token 或品質等效。`repair-execution.json` 是建立時點的收據；其 0 calls 不表示最終零用量，以另存的停止與最終結果收據解釋，沒有回寫舊證據。

### 尚未通過的門檻

- 模型不得將偏好擴成硬條件，亦不得新增使用者未要求的排除範圍。已加規則，repair case 仍違反；最後程式修正不能替代模型回歸驗收。
- 原生問題已產生並在介面顯示，但提交選項後的新模型續答未完成本次驗收。
- 其他模型、effort、研究深度，以及不同地址／來源形狀不在這五次實測的保證範圍內。

所以目前可測、可研究、可追溯；不能把「同步問題已修」解讀為所有回答都已可靠。下次模型驗收應固定最後公開包，用新的多輪案例檢查上述獨立門檻；遇同類實質錯誤就停止並保存，不用重試次數換高分。
