# 真實資料與問題分級：有界驗收 v1

此輪回應使用者要求，接在已關閉的合成對話驗收之後。舊結果與分數保留，不能回填成真實搜尋通過。Claude 繼續暫停。

## 優先順序

| 級別 | 問題 | 本輪處置與判準 |
|---|---|---|
| P0 阻止交付 | 編造／過時資料冒充目前可租、錯戶、違反硬條件、未授權聯絡付款 | 有此情況即 veto；網址不代表來源已核對。這是风险門檻，不是宣稱已觀察到全部問題。 |
| P1 先修 | 真正找房卻只能給虛構候選；正式 onboarding 鼓勵虛構 fallback；目前 UI 禁止搜尋；安裝版本過舊 | 移除默认虛構 fallback，新增可實際搜尋的本機路徑並核對實際載入版本。來源失敗不能變成假成功。 |
| P2 後修 | 反覆來源公告、流程術語、無助推進的開場、重問已答內容 | 來源標示隨資料保留、就近說明限制；完整可見對話仍須通過獨立 UX gate。嚴重或反覆阻塞時升 P1。 |
| P3 微調 | 簡短提及使用者指定的量表名稱 | 不做字串禁令；只有誤導、搶佔答案或增加修正負擔時升級。 |

## 三種測試分開

1. 合成 fixture：固定極端條件、故障與安全回歸；明示測試資料，不聲稱是真房源。
2. 真實快照：公共來源的事實摘錄、原 URL、取得時間、證據範圍；測固定資料的比較，不能宣稱目前仍可租。
3. 真實搜尋：新 session 從現在的公開來源取得少量資料；保留查詢事件、來源與失敗。測的是實際研究能力，不能替代可重現回歸。

## 呼叫預算與版本

最多 4 次 GPT-6 Astra actor 呼叫，effort low，共 600,000 processed tokens，單次至多 300 秒。兩輪同一 live 對話、一輪真實快照比較、一輪來源缺失／過期處理。只有 root dispatch，沒有自動重試、模型切換或 persona 隱藏呼叫。一個工具型 turn 可包含多次檢索；tokens 上限只能在 turn 間阻止下一次，不能保證單次不超限。實際 prompt/config/程式 hash 在 dispatch 前凍結到私人 run manifest；修改後需新版本，不覆寫舊輸出。

Root 和 Astra subagent 的研究／評審用量另列為 host 未提供逐次 receipt，不能聲稱零 token。模型失敗、空回覆、schema 失敗或來源失敗都保留並計次。舊 192 次矩陣不重開。

## 情境與評審

Actor 只取得該時點使用者要求、當前 skill 和當時可見來源；不看到評分答案或未來追問。先要求少量倫敦真實比較例子，再插問與調整偏好；固定快照檢查廣告面積不冒充 EPC、月份不冒充特定入住日、房租不冒充總花費。來源失敗檢查下一步是否實用，且沒有捏造房源或偷偷聯絡。

保存全部 user/assistant/progress/tool/usage，以及 UI 實際呈現內容。獨立 Astra evaluator 看全段、來源及使用者反應，判首句、是否回答問題、比較／推進、修正負擔、條件延續與證據正確性。Root 複核評審過程與抽取的來源；不以平均分抵銷硬性 veto。沒有真人反應的地方明確標為 scripted，不推論使用者滿意。

一次成功只證明這個版本／模型／來源當下通路可用。跨模型、失效來源覆蓋及長期可靠性需後續獨立驗收。
