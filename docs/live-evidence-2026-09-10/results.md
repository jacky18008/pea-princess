# 真實房源、對話問題分級與驗收

研究始於 2026-09-10，後續修正跨至倫敦時間 2026-09-11。本報告與原始實驗分開保存；歷史失敗不因新版修正而改分。原始使用者要求、逐字對話、來源與獨立 Astra 評審留在本機私有目錄。

## 交付方向

正式找房預設使用真實來源。「給幾個例子」代表拿實際房源幫使用者理解取捨，不自動授權編造。只有明確要求虛構教學例子才使用合成資料。查不到時，說清楚缺哪一項證據並推進可做的比較，不能補出假地址、價格、鏈結或可入住日期。

測試採三條路徑，結果分報：

| 路徑 | 用途 | 不能代表什麼 |
|---|---|---|
| 合成案例 | 可重現的邊界、條件變更與故障測試 | 真實市場、能找到房、真人滿意 |
| 固定真實快照 | 核對戶別、租金、樓層、日期，降低網頁變動干擾 | 今天仍在租、未來指定日期能入住 |
| 即時真實研究 | 實際搜尋、原頁、來源保存及追問接續 | 一次成功不證明全部網站、模型與研究深度可靠 |

「真實廣告」與「已確認能租」必須分開。刊登在線、HTTP 200、大樓起價、同棟另一戶及宣傳用語，都不能替代指定房源和入住日期的確認。

## 嚴重度與修復順序

| 等級 | 問題／升級條件 | 本輪處置與界線 |
|---|---|---|
| P0：立即擋下 | 編造可租房源卻稱已核實；已知硬條件不符仍推薦；越權聯絡、付款或洩露資料 | 這是最高風險類別，並非宣稱本輪已發生全部事件。不能用文筆高分抵銷。 |
| P1：核心工作或證據失效 | 要真實找房卻預設虛構；有工具卻被測試設定關閉；來源只有模型自述；損壞來源默默退回舊資料 | 移除 production 虛構 fallback，新增 live 介面與明確工具政策，保存獨立來源快照；完整性缺口已在 0eb0992 修正並做故障測試。 |
| P1：流程誤阻擋 | CLI 啟動警告被當成工具呼叫，成功回答無法交付 | 第三次實際遇到。保留失敗與用量，窄範圍修正分類；不重跑該案例洗成成功。 |
| P2：理解、等待與修正負擔 | 重複免責、逐項複述、回答前等待過久、時間戳佔據聊天尾巴 | 精確時間移入紀錄；來源標示在首次／變更時提供。首輪等待約 99 秒且只有 busy 狀態，仍是待改善體驗。反覆阻礙決策時可升 P1。 |
| P3：局部措辭 | 簡短、正確地使用使用者指定量表名稱 | 不做關鍵字式封殺，不優先於找房能力；若遮住答案、假裝權威或迫使用戶管理內部流程才升級。 |

「先用幾個虛構例子」的問題取決於情境：明確的教學示例可以；使用者期待真實研究卻被替換成虛構內容，屬 P1。誠實揭露虛構本身不是錯，不能為了順口而隱瞞來源。

## 根因與實作

三處設定共同造成落差：舊 onboarding 含無法搜尋時用示例的路徑；原 persona lab 固定注入合成人物／房源且關閉工具；本機已安裝 skill 仍是舊版個人化單檔。只改開場句無法解決這些原因。

`references/listing-evidence.md` 現在定義真實來源、戶別、時間、未知與例外契約，SKILL、onboarding、inputs、area-sweep 和使用指南同步。通用版本不繼承歷史個人找房條件。舊的本機 skill 已完整備份在私有實驗目錄，新的公開套件已同步安裝；已開啟的 agent session 可能仍持有舊指引，需要新 session 重新載入。

本機介面預設「真實找房研究」，輸入需求後才啟動，回答後等實際使用者追問。合成人物測試保留獨立入口及明確標示。真人插問無論 UI 種類，都逐字依序保存並注入後續；這是條件保留，不是假稱已自動完成語意抽取與所有 eligibility 核對。

runner 的 `text_only`／`live_research` 寫入請求、manifest、controller 與 recovery 核對，不能靠復原偷偷更換工具權限。研究使用使用者自己的 Codex；沒有增加遠端 worker 或託管帳號。唯讀設定與指引不等於獨立 OS 沙箱，仍需遵守 [安全界線](../../SECURITY.md)。

## 來源保留做到哪裡

原生 CLI JSONL 保留搜尋／開頁動作，但沒有回傳完整頁面內容、頁面狀態與每頁精確時間。v1 的「保留來源」驗收因此失敗；actor 說查過不能自己證明查過。後來另抓原頁能佐證資料，不能改寫模型當時看到什麼。

新增 `tools/public_source_snapshot.py`，actor 回答後由本機獨立抓取最多三個引用 URL，保留原始 body、文字、UTC 時間、hash 和錯誤。只支援明列的五個 operator 主機；HTTPS、公開 IP、固定 IP 的 TLS 驗證、不跟 redirect、不帶 cookie／帳密／proxy，每頁最多 2 MiB／10 秒，不自動 retry。超出三個 URL 仍保留未抓取狀態。

後續回合核對 hash 後注入小型快照全文，每篇最多 16,000 字元、合計 32,000；太大的原檔仍在磁碟，context 明示未提供正文。這些來源是不可信資料，不得授權工具或修改需求。本文不把抽取文字等同看過照片／平面圖，也不把快照當成自動查證答案。

實際 live followup 的 manifest 同時包含兩則完整使用者要求及兩篇匯入的原頁文字，標明它們是先前回答之後的獨立擷取。回答完成後，host 也自動保存了兩篇新的 HTTP 200 快照。這分別證明本例的匯入快照注入與回答後自動保存；沒有再買第三個 live actor 來證明它讀到新生成的自動快照。不涵蓋所有棄用線索或所有 host。

## 實際四個 slot 與用量

三份計畫依版本保存。v1 最多四次、600,000 processed tokens；第一則 738,985 超過停止線後停下。v2 將跨版本總停止線明載為 1,100,000，仍最多四次。這是呼叫間停止線，單一工具密集回合可能超支。v2 第三次因 controller 分類錯誤停下檢查；修正後最後一個 slot 另版執行。

| Slot | 版本／資料 | Processed tokens | 觀察 |
|---|---|---:|---|
| live-first | c858137，即時搜尋 | 738,985 | 真實 Highgate／Hammersmith 廣告，首句先比較空間與租金；未將安靜或十一月入住說成已確認。原始來源正文未保留，P1。 |
| live-followup | c99a87f，跨版重播＋真實快照／重開現有頁面 | 66,218 | £2,100 新房租上限排除 Highgate；暖氣費未知，Hammersmith 朝向待核；沒有新增房源。 |
| real-snapshot | c99a87f，固定真實摘錄 | 18,512 | 一房 13 樓、兩房超租金均排除，大樓起價不冒充合格戶。模型完成但 controller 停止，分開評分。 |
| source-gap | 0eb0992，固定真實摘錄 | 18,160 | 不把十月廣告月份當成十一月十五日的確認；£2,155 是房租，不是每月全部開銷。controller 正常交付。 |

**四次 physical actor 合計 841,875 processed tokens；沒有自動重試。** 三次 runner 正常交付，一次保留 controller 失敗。root 與 evaluator 自身用量未單獨量測，不能稱為零或包含在這個 actor 總數。所有輸入是驗收腳本，不是真人滿意度觀察。「原頁打不開」是 source-gap 的測試設定，不能報成真的網站故障。

v1 的 737,097 input + 1,888 output = 738,985；651,392 cached input 已包含在 input，不能再加。約 88.4% 的 input 是 cached。11 個獨立 web items 包含五組搜尋、五次明確開頁及一個不透明動作；23 events 含 started/completed 配對與啟動 warning，不是 23 次搜尋，更不是數百次 actor 呼叫。沒有逐步用量，因此不能精確歸因每一次搜尋的成本，也不能直接換算訂閱扣額／帳單。

v2 改成依需求載入通勤、區域掃描及補件細節，初步研究採一批搜尋、兩篇原頁、至多一次替代查詢的提示策略，並使用 [Codex 官方設定](https://learn.chatgpt.com/docs/config-file/config-reference) 的低 web context。提示策略不是程式硬上限。當前需求全部保留。第二則的任務不同，不能用 66,218 對 738,985 推出因果節省率；新版初始搜尋尚未重跑。

## 如何評，不讓高分掩蓋問題

獨立 GPT-6 Astra 分開檢查：首個實際可見句子、當下問題與推進、澄清負擔、跨輪條件與未知、来源對應、controller／用量、實際產物。root 再核對評審是否真的看到了證據，缺失標 unknown，不用平均分抵銷必要 gate。

原 v1 首句 UX 在此案例通過，但來源保留失敗，不能稱整體通過。獨立 Astra 對 v2 追問、固定比較原答與 v3 日期／費用回答均給有限範圍通過；固定比較的 controller 交付仍失敗。v3 再以離線復现確認兩個完整性缺口已修正，沒有回寫歷史評審。後補原頁與 hash 佐證兩間價格、房型、面積來源、廚房、樓層及宣傳用語；原未知評審留存，後補結論另寫。discarded leads 仍無完整原頁證據。

UI 只顯示 final message，CLI 早先兩則 progress 僅在原始紀錄；不能把較好的隱藏 progress 當成使用者實際看到的首句。root 也實際檢查本機 UI：Markdown 鏈結、比較表與最多三題選項控制正常，歷史版本可閱讀／匯出，不能默默套新版繼續跑。
