# 真實資料驗收 v2：停止後的修正與剩餘三次

v1 第一則在 c858137 執行，737,097 input + 1,888 output = 738,985 processed tokens，越過原600,000停止線。因此原計畫停止，沒有自動發下一次。其651,392 cached input已包含在input，不另加；processed tokens不能直接當帳單。後續使用使用者已授權的修正／多輪實驗範圍，本次仍維持總共最多4次actor，將跨兩版的停止線明確調整為1,100,000 processed tokens。這是研究操作界線，不改使用者租屋預算或訂閱方案。

## 修正

- 初步發現不再固定注入整份區域掃描、通勤及補件／API說明；根據目前完整使用者輸入選用相關原文。當前使用者要求、skill、來源契約和對話品質指引仍保留。這不是無損壓縮的實驗證明。
- 小型發現採一批搜尋、兩個原頁、至多一次替代查詢的工作指引。這是提示策略，不是假裝存在程式化工具次數硬上限。Codex web search context size設low；原廠欄位見[官方設定參考](https://learn.chatgpt.com/docs/config-file/config-reference)。
- 本機host在actor結束後，針對最多三個引用網址，獨立保存公開HTML／抽取文字與UTC時間及hash；超限、不支援、阻擋、截斷或失敗都保存狀態。只支援列明的五個公開operator主機，不跟隨redirect、不帶cookies／帳密／proxy；DNS只接受公開IP，連線固定到該IP並驗證原主機TLS。每頁2MiB、10秒、沒有自動retry。這不是模型當時看到的原始tool內容，也不證明主張或可租狀態。
- 下一輪注入完整的小型快照，核對hash；單篇超過16,000字元或總正文超過32,000時明示只提供metadata，需要原文時重開公開來源。保留原檔，不默默裁切使用者條件。精確時間留在紀錄，不把技術時間解釋變成聊天尾巴。

## 剩餘三個slot

1. 保留v1兩則可見對話，建立有來源hash的v2重播副本；匯入後補上腳本追問，檢查收緊房租預算、噪音排除條件和暖氣費問題。這是跨版本重播，不冒充同版不間斷對話；本次不重新跑初始搜尋，不能推出v2初始搜尋的品質或節省比例。
2. 依真實固定快照比較樓層、房型與房租；不搜尋。
3. 依固定快照與「本輪無法取得目前原頁」設定，區分廣告月份、特定入住日及房租／全部開銷；不搜尋。不把測試的缺來源設定稱作實際網站故障。

三次仍採Astra low，單次最多300秒；未知用量或新實體失敗停止檢查，沒有自動retry。模型全部原輸出與失敗保留，root及獨立Astra評估另存。未跑的slot維持未測；不重新標記v1為通過。來源獨立擷取不消耗另一個actor呼叫，但研究／評審本身的host模型用量不可聲稱零。
