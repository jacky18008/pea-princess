# Benchmark runner security and process review — 2026-09-09

Reviewed the benchmark runners, launcher, latest call controller, handoff notes, and experiment protocol against baseline commit `cb9ed3e`. No benchmark CLI/model call or external HTTP request was made. Reproductions use disposable Python processes, mocks, and temporary files. Historical measurements and raw files were not edited.

## Findings and corrections

| Severity | Finding and precondition | Correction |
|---|---|---|
| P1 | `worker_eval.py` described a no-tools document test but launched Claude with its ordinary tool/config surface, inherited repository cwd and open stdin. Persona/chat helpers used `--allowedTools ""`, which grants no extra permissions but does not remove built-in tools. A hostile pasted document could ask for tools or inspect unrelated local material, subject to the runtime's remaining permission checks. | `launch.claude_tool_flags()` separately sets available built-ins with `--tools`, preserves the allowed permission patterns, supplies empty strict MCP configuration, excludes user/project/local settings and disables hooks. Empty-tool actors also disable slash commands. The worker now uses a fresh private temporary cwd, closed stdin, and `--` before the prompt. This change reaches Claude commands built by `run.py`, journeys, personas, document benchmarks and pipeline roles. |
| P1 | `journeys.api_post` put the bearer API key in curl argv during TLS fallback. Its urllib path also used normal redirects for a credential-bearing request. This could expose credentials to process inspection or forward them through a redirect. | API requests now use the shared hardened `_fetch.post_json` transport, passing no URL/key/body in argv and using `cache_ttl=0`, `min_gap=0`. It disables curlrc, limits HTTP protocols and refuses authenticated redirects. Non-2xx bodies and status remain available to the caller. Transport diagnostics do not echo the request URL/key. The fetch implementation and its transport tests are covered by the companion fetch review. |
| P1 | The legacy launchers killed only their immediate child on timeout. A child could keep doing work and hold stdout/stderr pipes open after the declared timeout. The outer A/B sweep also applied each timeout when it began waiting rather than when that process started. | Owned POSIX sessions, bounded process-table snapshots, common cleanup deadlines, explicit group cancellation/reaping and cancellation forwarding cover ordinary nested runners. Registered children are also cleaned up when a wrapper exits normally. Cleanup permission failures raise `ProcessCleanupError`, rather than reporting successful containment. The sweep uses monotonic elapsed time from each launch. |
| P2 | The common launcher retried by default and returned only the final attempt's usage. A retry with unknown usage could look like a complete, cheaper result; timeout output was discarded. A zero-exit Claude `is_error` envelope could be treated as success. | Default attempts is one. Explicit retries retain per-attempt usage, exit status and captured tails; aggregate usage is null if any attempt lacks coherent input/output telemetry. Failed and timed-out attempts retain available evidence. Explicit error envelopes fail even on exit zero. Journey, persona, document and pipeline records retain attempt evidence. |
| P2 | Legacy Codex parsing could merge separate incomplete holders into a fictitious complete usage snapshot, or accept an explicit total inconsistent with input plus output. | The fallback now uses one holder, never merged counters. Legacy prompt/completion aliases normalize within that holder. Conflicting totals/aliases are marked unaccepted; partial and nonfinite telemetry cannot become an accepted complete launch total. Raw diagnostic counters remain available. |

## Reproductions and validation

Before the fix, a parent with a one-second timeout left a child running long enough to write a marker at 1.4 seconds. The supposedly timed-out call returned after the surviving child closed its inherited output pipe. A two-attempt mock with 20 + 3 and 30 + 4 tokens returned only 30 + 4 instead of 50 + 7.

Focused regression tests now cover:

- Descendant cancellation, preserved timeout usage, and a nested runner whose child ignores SIGTERM.
- Six resistant children, each in its own session, under both outer timeout and direct SIGTERM interruption.
- A wrapper that exits normally after registering a child: the child cannot later write its marker.
- Permission-denied cleanup surfaces as a failure; it is not reported as verified termination.
- One-attempt defaults, all-attempt sums, missing/partial/nonfinite usage, nonmergeable partial holders, inconsistent totals, legacy aliases, and long zero-exit error envelopes.
- Actual generated Claude availability/permission/MCP/settings flags, closed stdin, API requests with caching disabled, retained HTTP error bodies/status, and diagnostic redaction.

The launcher suite passed **55 tests** after the final lifecycle and accounting changes. The other focused suites passed: A/B **93**, journeys **74**, personas **105**, pipeline **85**, document benchmark **110**. The main review records the subsequent complete integration-suite result. These tests do not contact a model provider.

## Boundaries that remain

1. **Read-only is not source isolation.** Legacy Codex helpers/runners still permit reads and may inherit user configuration. The latest ablation uses ignored user config, a read-only sandbox and post-call rejection of tool events; its completed 156-call run had zero observed tool events. That is observed compliance, not preventive proof that private files could never be read. Before using genuine private material with an untrusted document, use a runtime with enforced tool/source boundaries and a dedicated filesystem/environment.
2. **An allowed Python interpreter is broad code execution.** `Bash(python3:*)` permits Python functionality, not only repository fetchers. The new `--tools` boundary removes unrelated built-ins; it does not turn Python into a restricted fetch API or constitute an OS filesystem/network sandbox. Trusted local research and hostile multi-user service workloads need different isolation.
3. **Process cleanup is lifecycle control.** The POSIX process table can race, permissions can deny signals, and unavailable `ps` falls back to initial process groups. A process deliberately daemonized/reparented before capture, `os._exit`, or an external SIGKILL of the supervisor is outside the verified cleanup guarantee. This is not a container/cgroup security boundary. Detected signal permission failures are explicit failures.
4. **Batch and budget policies differ between generations.** The latest `CallControl` persists dispatch before execution, locks state, rejects unresolved/failed replay and requires complete direct telemetry. Some older matrix runners still move to later jobs after a failed row; the new one-attempt default does not create a universal batch circuit breaker. Use the paused persona recovery's bounded canary policy, and migrate future studies to the durable controller before large unattended batches. The reported-token threshold is checked between calls, so one call can cross it; it is not a prepaid invoice or subscription quota cap.
5. **Saved defaults are not a pinned model.** Legacy runners can still accept an omitted model. Explicitly pin all target/helper models when starting a new run and preserve the source/config manifest. Do not combine new hardened-runtime results with old trials as if their execution conditions were identical.
6. **Raw evidence remains private operational data.** Gitignore and checksums are useful but are not access control or anonymization. Keep original prompts, output, stderr, helper traces and private gold in owner-only directories/backups, and review selected artifacts before any publication. A new attempt ledger contains diagnostic tails, so it needs the same treatment as raw output.
