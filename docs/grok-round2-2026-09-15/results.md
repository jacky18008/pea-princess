## Pilot 費用與 durable state：可見文字、自述和直接核對分開

**費用是已觀察的 P2，用未知當零使比較可能偏低；Astra 沒有判出已證 P0／P1。** Bot 在 19:34 final 用兩戶各 £175 水電網路等規劃值、£0 council tax（理由是 B 缺戶號／稅級），算 A **£2,625**、B **£2,275**。加法 £2,450+£175+£0／£2,100+£175+£0 算得對；問題是 council tax、社區供暖 tariff／standing charge、其他 bills 未有 source，**未知不是已證的 £0**。A 已有同地址 EPC 的 community-heating 訊息，B 同戶仍未知，不能把街段熱網樣本當兩戶都已確認 £175。廣告租金差 £350 是可算的；這不是已知 all-in 差。以 £0 占位可能低估必要費用並讓兩戶看似可比。v3 [all-in cost reference](../../skills/vet-flat/references/axes/10-all-in-cost.md)、schema、calculator、renderer/viewer 和 requirements panel 已改為讓 unknown tax 保持 unknown；修復已在預登記 v3 程式碼通過 full offline suite，但 **v3 native outcome pending**，不能追認 v2 native 答案正確。接受 gate：已知 rent 與未知 council tax/heat/bills 分欄；只有有來源或明顯標成 scenario 的數字才產生總額，沒有零稅證據時不能顯示「完整月費」等於租金＋£175。

Root 在第一品質 Bot 的 `/workspace/pea-princess-round2-rental` 直接**列檔**：`.pea-state/boundary-context.json` 3,542 bytes、`boundary-review.json` 12,283、`events.json` 7,573、`identity.json`，兩個 `area-scans`；`reports/comparison-A-B-2026-09-15.md` 837 bytes；notes/source files 及 `notes/reply-check.err`、`notes/boundary-reconcile.out/.err`。**Formal journal files present**，不同於舊包真實 Episode 1 的 Greenwich project revision 5 只有 plain comparison/decision files、`tasks:{}`／`decisions:{}`、僅 `beds` mapped、u1/u2/u3 pending 的 P2。檔案**存在**不能直接推出 project request 完成、formal permission 或 current registered output。

後續 Bot native **自我稽核**（尚非 operator 對 raw state 的獨立 parse/verify）報 `.pea-state` revision **11**、`verify` **11 events OK**、`documents:0`、`decisions:{}`、`tasks:{}`、`outputs/facts/dispatches/budgets` 皆空，u1/u2 resolved；`boundary validate` 在 rev11 回 `valid:true, ready:true`。它聲稱相同 revision 的 `boundary-review.json` SHA-256 以 `49bc9f44…` 開頭，`todos[1]` A、`todos[3]` B 為 `action:"viewing_permitted"`、`requirement_ids:[]`；A/B 候選 `status:"needs_evidence"`、`viewing_allowed:true`、`consent_holds:[]`、`open_requirement_ids:[available,bedrooms,commute,no_contact,quiet_bedroom,rent]`。依 [boundary-turn.md](../../skills/vet-flat/references/boundary-turn.md) 的 route，`boundary-review.json` 與 `boundary-context.json` 本來就是 reconcile 同 revision 保存的**目前機器比較和 TODO 工作清單**；這項目前審查有 durable save 的自述證據，不應僅因 `outputs/documents/tasks/decisions` 空便判整個保存要求失敗。這條 route 同時明說它**不是完整 assessment/report workflow**，且 generated comparison 不是新 evidence source。Bot 說 `viewing_allowed:true` 表示已記 hard gates **沒有阻止考慮看房**，不表示已取得人對 agent-side contact/booking 的 permission；`no_contact` 仍 active。`viewing_permitted`／`viewing_allowed:true` 容易被讀成完整 consent，而 typed decisions 空使 scoped user choice 如何記錄仍需 raw clarified。**不能在看到實際檔案前斷言 A/B 已被授權約看、也不能斷言 agent 做了被禁止的外部動作。**

稽核還自述 source/tool/result paths、report/notes hash；這些不是該 Bot 以外第二讀者對 raw 檔案位元組的證明。`notes/reply-check.err` 存在亦非 checker 對送出 draft 成功執行的 trace；Grok 實際 `reply_check.py` invocation count **unknown，不是 0**。精確 model、effort、token、完整隱藏工具／provider request 次數 unknown。下一個只讀稽核應在同一 current project 讀 `session_state.py context`／`verify`、events hash chain、boundary review/raw TODO、plain report/notes 的 source refs 和 stdout/stderr 實際內容、mtime/sha/revision；對照**實際受損 native user turn**，不能靠 model-authored quote 還原凍結 consent。審查須分開認定：rev11 生成的 machine review/TODO 是否為 current、plain prose report 是否由同一 current evidence 推出、完整報告是否另需 registered output/task。最後一項是 workflow scope 選擇，不能用 boundary route 的空欄位直接反推失敗；在缺獨立 raw provenance 時，只能說**部分 durable save 已由 Bot 自述、文字報告 current provenance 未核**。即使 raw 後來驗證，受損 pilot 仍不可併入 3 次 repeat。


獨立 Astra 對這條 pilot 的判讀是：**未知 council tax 被寫成 £0 的「完整月費」為 P2；registered outputs／typed decisions 缺席，使完整文字報告的 current provenance 和 scoped choice 沒有機器登錄證據，亦為 P2 待釐清項**。後者須按 boundary route 的實際範圍修正：rev11 machine review/TODO 已有自述的 durable save，不可稱「完全沒存」；缺完整 report task/output 是否超出 route，需先決定 workflow scope。這是 severity review，並不把 Bot 的自我稽核升格為 operator 對 raw journal 的驗證。Native 輸入損壞與 Codex j12 舊全域 skill 是測試有效性／acceptance blocker；目前沒有經核實的 P0/P1 security 或被禁止的外部聯絡／預約。需讓 raw state parse 檢驗 P2 的具體範圍與原因。

## Checker 與 host／package attribution

舊合成六回合**六則完成可見 actor reply**離線 checker 的 `decision` 命中僅 **turn 2 final「A 目前可排看房」一次**；舊 turn-4 的「B 的例外已拒」在保存 TODO/historical state，另算一個離線 hit，不是第二則可見 reply 或第二個 episode。Operator 另外直接讀了舊 scoped export tar.gz 的 `MANIFEST.json`：`.six_rounds[].tools_verifiable` 的**6/6 回合 tool-label arrays 都列 `reply_check.py`**。這是 actor-generated export manifest 的**標籤自述**，完整底層 Grok tool-call trace 仍未取得，不能據此聲稱 checker 在 6/6 真正執行，實際 invocation count 仍 **unverified**，更不能寫 0。兩個離線肯定例子語意上把「可考慮」／未答提議寫得更強。整合 [reply_check.py](../../skills/vet-flat/scripts/reply_check.py) 命中這兩句；[tests](../../tests/test_reply_check.py) 保留人原話、proposal、negated history 的反例。v2 `DECISION_NEGATION` 已免除「B 不該被當成可排看房」「B is not booked」的舊誤報；「A 你可以自行安排去看」仍可能因沒 regex cue 漏出，另有「我已拒絕把 A 的 EPC 套到 B」這類 subject 不是人決策的誤報。故 **regex 0 hits 不是 semantic consent pass**，需 reviewer 核 exact quote／candidate／research-viewing-contact-book stage。Claude Code 的 Stop hook 是該 host 的做法；Grok Bot 未有已證同等 hook，不能把 Claude 0/90 的 checker 自行執行數字移給 Grok。

第一品質 Bot 有公開 TfL/Defra 資料活動；其成本未知、完全 tool receipts 未得，不能一例判「所有來源可靠」或把資料解讀錯全歸 host/model。Doctor 首次 Defra unknown、同機第二次成功是**來源特定間歇**，不是無網路的宿主特性。UI/IME corruption 與 concurrent ZIP-only Bot 是 transport 事實，不是公開 package text 的邏輯錯。費用 unknown-as-zero 是 v2 回覆行為，v3 做了 code/schema 修復；需要新 native cohort 才知修復有無實效。Formal boundary review 的 `viewing_permitted` 命名／typed decisions 空缺兼有 package schema、actor 使用與 host 出口檢查因素，須 raw 狀態和跨宿主同 fixture 才能分攤；任何一個檔案名或 model self-report 都不建立因果。

## 跨宿主 j12：目前不是新包 baseline
