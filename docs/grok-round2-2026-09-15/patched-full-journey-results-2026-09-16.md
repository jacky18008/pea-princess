## Usage interpretation and remediation priorities

The raw CLI totals expose fresh, cached and output tokens separately. xAI's [API cost tracking](https://docs.x.ai/developers/cost-tracking) defines 10¹⁰ ticks as US$1 for API calls, so our `/10^10` figures describe an **API-equivalent metric** from consumer OAuth CLI receipts; they are not verified billed subscription dollars. xAI's current [consumer FAQ](https://docs.x.ai/grok/faq) describes a shared weekly usage pool whose percentage, product breakdown and reset appear in **Settings → Usage**; heavier coding tasks consume a different pool share than chat. The one previously seen Grok Bot account label `X Premium+ 28%` was observed only after earlier calls and without a reliable refreshed before/after or denominator. Neither processed tokens nor API-equivalent ticks tell us how many journeys a $20 or ~$31 subscription can run. An unlocked, refreshed Usage reading before/after a controlled standard-depth journey is needed; without it, the measured 5.14-million-token follow-up is a warning about inefficiency, not a computed subscriber quota impact.

The previously frozen old-version six-turn trace consumed 14,544,862 processed and 198 tools; this corrected-package trace consumed **9.66% more processed tokens** (15,950,418) while using fewer tool calls (185). Its provider API-equivalent estimate is **22.48% higher** ($4.42307904 versus $3.61110056). The samples use a different package and nonrandom model trajectories, and source capture/fidelity differed, so this comparison does not identify a causal token effect or quality-neutral saving. Moving deterministic work to a native host and measuring both live quota percentage and independent quality would test whether cost improves without losing conditions.
