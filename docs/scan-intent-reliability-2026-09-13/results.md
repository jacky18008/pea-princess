# 掃描中斷與條件強度：修正紀錄

兩個程式缺口已修正並整合至 main：掃描有截止時間、部分保存及執行者消失後的狀態恢復；支援的使用者條件由 host 保存、在發布前核對。V2 Terra 完成一次真實掃描，V3 的兩輪已通過獨立條件一致性與對話複核。**完整四輪驗收仍未完成**，不能將不同版本的成功片段拼成完整通過。舊實驗的逾時與未知用量保持原樣。

## 是否因為網路斷線？

有可能，但無法從舊紀錄確認。舊呼叫在 300.2 秒後被控制層停止，scanner 結果仍為 `running`，之後檢查時原 PID 已不存在；當時沒有保存各來源進度，無法區分哪個來源卡住、網路斷線或其他延遲。用量未知也仍是未知。

已確認的程式缺陷有兩個：掃描沒有整體／各來源截止時間；執行者退出後，讀取端不會把遺留的 `running` 收尾。因此恢復網路本身不能修正保存狀態。

## 本版改動

- 整體掃描預設 180 秒、單來源 90 秒，參數最高 240 秒，保留 host 300 秒期限前的收尾空間。已完成來源逐項保存；逾時或中斷後留下部分資料及原因。
- fetch 在節流與網路等待中檢查截止／取消訊號，終止及回收自己的 curl；不在取消後偷偷派送下一個批次請求。
- 讀取自己的可變研究資料夾時，host 以非阻塞檔案鎖確認是否仍有執行者。執行者消失才把遺留項目標為 `interrupted`；不猜 PID、不殺別人的程序、不重新掃描。
- 模型問題前綴、實際選項、自填答案分開保存。只有實際答案進入使用者條件來源；完整 raw UI 紀錄仍保留。
- host 為支援的安靜／採光條件建立來源與版本綁定的狀態；模型不能用自填 JSON 修改它。發布前核對條件集合、強度及已知的正文矛盾。新訊息到達則擋下舊版本回答。
- 原始被攔回答、用量和原因留在 Inspector／匯出，不自動呼叫模型重寫。重播選項仍向原始控制項驗證；使用者中途取代的重播回合記為 superseded，不冒算完成。

## 離線驗證與獨立 review

V3 完整 Python suite：**2,811 項，通過，18 項跳過**；對話 UI、Inspector 與 community 的三組 JavaScript 功能檢查通過。變更 Python 檔通過 Python 3.9 語法檢查。新版 ZIP 包含 106 個成員，已逐檔核對本次關鍵程式／文件與工作版本一致，未混入私人 runtime。

覆蓋斷線類停滯、執行者退出、仍存活的 lease、完成／恢復競態、慢 checkpoint、fetch 取消、錯誤／缺失 metadata、正文矛盾、否定句、提議未採納、表單偽造、重播再重播及中途插話。

獨立 review 找到並修掉三個具體反例：完成結果可能因慢 checkpoint 被誤判逾時；不完整結果仍帶有 Complete 指示；「不要把安靜列為必要條件」曾被解析成必要條件。另修正重播後模型問法改變導致原選項來源無法驗證的問題。測試不只檢查接受成功，也檢查應該拒絕及不該誤拒的情況。

以**舊逾時紀錄的私人副本**執行新恢復程式，結果從 `running` 變為 `interrupted`，無新網路／模型呼叫；原檔 SHA-256 完全不變。這證明可收尾該保存格式，不證明舊逾時由網路造成，也不能補回當時未保存的資料。

第一遍全 suite 曾因測試依賴私人歷史檔，以及驗證期間其他子代理正在修改來源而失敗。已將舊矩陣測試改為自行建立合成資料；待來源穩定後重新執行全 suite，得到上述通過結果。第一次失敗 log 與最後 log 都保存，沒有冒充模型失敗或抹去。

V1 的初始化缺陷是程式錯誤，不能歸因於網路。修正後新增從 postcode／street 經真實 scanner 與 checkpoint 路徑的離線回歸；70 項 lifecycle 與 19 項 fetch 檢查通過。舊 V1 快照及失敗紀錄原樣保留，沒有重命名為 V2 成功。

V2 的安靜仍是偏好。獨立 Astra 與 root 都認為「我會建議放棄」是分析者自己的建議，不能單憑語氣強烈認定為使用者硬條件。真正的偏差是：已退休的「早上直射陽光」被描述為改成偏好；目前僅為偏好的普通採光，被說成已採納加分項。JSON 與保存狀態正確，正文卻不同，因此 exact-state publication gate 不通過。

Astra 將此正文不一致評為 P1；root 認為依既定分級應是 **P2**，因為未證明新增硬條件、舊版本回答或實際錯誤淘汰。保留這個分歧，仍停止該組，不讓 metadata 高分抵銷正文問題。另一個 P2 是第一句把「查詢範圍未找到夜間場所」說成「這條街不是夜生活街」，強於地圖資料能證明的範圍。

V2 中模型另嘗試重複啟動一次 scanner，被 pending 鎖拒絕；沒有因此重做整批來源查詢。這是重複操作被攔住，不是模型從未嘗試。

五次實際 actor 呼叫合計 **1,135,594** tokens，在原先選定的 1,200,000 工作上限內；cached input 已含在 input 裡，未重複相加。這不是金額、訂閱剩餘額度或省 token 比率；開發與 evaluator 用量未含在 actor 計帳。V3 第一輪 226,688、追問 188,162，剩下 64,406 不足以合理預估再派送一輪，因此沒有加碼或重跑。預定的 advice-only T3 與實際 bonus 選項 T4 未執行，見 [V3 計畫](plan-v3.md)。

V3 第二輪正確說明：直射陽光的必要條件已取消，普通採光仍是偏好，沒有提前採納為加分項；安靜在 host 狀態中一直是偏好。Astra 與 root 讀完整前後文後，都認為較強的噪音淘汰說法屬於分析者建議，而非使用者新增硬條件；但孤立的句子仍容易誤解，列為 P3 用語問題。

另在 T2 後實際停止並重開自己的 8775 host：session 檔、匯出內容、兩份附件雜湊完全相同，模型呼叫仍是兩次，未自動接續。這證明該次保存／重啟，不能當作尚未執行的選項提交後續答。

V3 離線重驗保留的 V2 原文，確實攔下退休條件重新引入與偏好／加分不一致兩項；原始 session 檔及其歷史 claims 未修改。即使另給完全匹配新版 frame 的 metadata，正文仍被攔下。這是修補後的回歸驗證，不是新模型回答。

## 剩餘問題與下一步

- **P2：原有 reply_check.py 的來源格式檢查形成重複操作。** V3 T2 的八個完成工具項目是五次命令與三次草稿編輯，沒有新網路搜尋。其中三次執行草稿檢查，前兩次重複抱怨同一個 300 米數字缺少同句來源；模型最後刪去範圍才通過。這與新 host intent_guard 是不同檢查器。下一步應檢驗段落末引用的處理及同一診斷重複時的停止方式，保留有來源的範圍，不鼓勵刪掉資訊來過關。本次未修改這個舊檢查器，也不能量化各工具分別花了多少 token。
- **P3：建議的歸屬與精度。** 明確說「我建議把安靜度列為現場重點，再依你的接受程度取捨」；晨光角度不宜只限東至東南；區域 decile 9 應精確描述，不籠統稱最好的一成。
- **尚未驗證：** 同版完整四輪、advice-only 後不擅自採納、實際 bonus 點選後續答，以及重開後模型繼續工作的整段結果。相關程式／模擬 host 測試通過，不能替代這些尚未跑的原生模型回合。不同模型、effort、深度也不能從本輪推論通過。

## 邊界

這是有限文法的條件檢查，不能保證所有語言、隱喻、任意條件或新措辭都能識別。正確 metadata 也不是整篇文字的真值證明；候選排序與 TODO 仍須經相應的 eligibility 接口。來源成功不等於屋內安靜、房屋可租或資訊已獨立證實。

下載的公開 skill 包含 checker 與整合契約；這次測試台由 host 強制執行。其他原生 agent 若只閱讀文件，尚不能聲稱有同等強制把關。執行取消不是對抗惡意程式的 sandbox；自訂 Python 工作若永不返回，可能留下 daemon thread，不能因此宣稱通用程序隔離。
