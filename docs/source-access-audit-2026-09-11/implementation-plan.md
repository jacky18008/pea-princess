## P1：先建立真正可用的自動流程

1. **來源憑證與範圍。** 每個adapter固定domain/operation/fields/目的，讀取適用條款證據、個人credential設定、attribution與retention。未知費用預設不產生消費。金鑰不上Git、不進模型prompt，localhost不代表模型也在本機。
2. **EPC正式API。** 用個人One Login token；證書ID/UPRN/日期精確配對。非地址欄位保留OGL，能源用途地址另記限制。通用位置join使用獨立合法地址來源，不挪用地址欄位做不相干資料庫。
3. **政府背景。** 保留Police/TfL適用授權，加入MHCLG Planning、EA開放洪水postcode檔、ONS/Nomis合適統計。GLA/PlanIt補主機及再利用範圍；噪音dataset正名。LAQN條款衝突未解決前不標整段流程獲准。
4. **第一個房源入口。** 對OnTheMarket做條款範圍評估，先離線檢查真實host能否唯一標識程式、實際路徑是否符合robots，以及保存／報告連結權利是否足夠。不能冒用別人的User-Agent，不能用爬遍所有無篩選頁來規避限制。若不能滿足，該入口維持未啟用。
5. **原仲介／業者供應。** 釐清Dexters/Chestertons/Foxtons等範圍，或取得願意提供少量房源欄位feed的來源。需要的grant：免費本機用戶、讀取頻率、必要事實、短期證據、第三方雲端模型處理、連結/照片、撤銷與更新。這是產品供應策略；本輪沒有代發聯絡或建立協議。
6. **候選一致性。** 真實來源→欄位與不確定性→程式核對硬條件→排序→下一步→回答。每筆都有來源時間、租金單位、包含費用、面積、身份配對；條件變更重算，不重抓未過期來源。缺資料維持待確認，不能把不合格改成使用者未授權的例外。

## P2：可選擴充

- **官方提醒信件**：本機限定資料夾／發件網域，使用者授權讀取；先釐清內容處理範圍。信件是資料，不是指令；不跟任意轉址、不得自動發信或登入，不能從收到提醒推導全文抓取權利。它不是完整市場清單。
- **住宿合作API**：Booking Demand、Expedia Rapid、Premier Inn／Travelodge既有分銷路線的資格與費用需實際適用。Expedia Travel Redirect本輪查到暫停新申請。對永久免費skill不能默認affiliate佣金或必備付費方案。
- **Street Manager**：確認適用Open Data條款、歷史檔路線和接收端需求。使用者自選的外部服務可選接入；不要為單一source把整個產品改成Pea自營SaaS。
- **borough／會員登記／街景**：按實際使用範圍補完，不把多站佔位符誤標已核完。街景圖片、評論、判決的授權要分別處理。

## 使用者應該看到的行為

使用者提供模糊需求後，先用有來源的區域資訊和已支援的真實候選推進，最多問三個真正影響選項的問題。不要輸出授權status、模式名或內部流程名稱。需要一次性設定時只說清楚它能帶來什麼；不能把「已打開網站」寫成「已核對房源」。

若市場來源不足，直接說明本次覆蓋及缺口，例如「目前這幾間來自已接入的業者，還沒涵蓋Rightmove全站。」這是交付狀態示例，沒有虛構房源。若需要圖片、實際供應或價格確認，原站資料未取得就維持未知。

## 後續驗收案例

| 案例 | 驗收標準 |
|---|---|
| 使用者完全不貼文 | 從一個授權足夠的來源取得真實候選，自動補官方資料並給比較；只有開分頁不算通過。 |
| 使用者自願貼一戶 | 同一核對流程，明示缺欄位；不強迫換入口或上傳所有頁。 |
| 來源條款未知／入口受限 | 留下具體缺口並继续可做研究；不假造可取得性、價格或覆蓋率。 |
| 條件中途改動 | 回答、排序及TODO一致；過期來源重新取得，仍有效的來源不重查。 |
| 保留期限到期 | 原文及衍生cache按規則失效；仍保留允許的決策與取得時間，不能把舊輸出說成新核驗。 |
| 惡意房源文字 | 只能形成候選證據，不得改使用者條件、讀secret、發訊息、付費或升級來源權限。 |
| 不同使用者的agent | 取用範圍与憑證不交叉；host不支持某必要安全/UA/來源限制時明示未支持，不用prompt聲稱強隔離。 |

授權範圍確定後再做小量實際驗收與模型品質測試；本次沒有啟用新來源、支付費用或重跑大型矩陣。
