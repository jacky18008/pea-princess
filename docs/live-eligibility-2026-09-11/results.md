# 真實房源與條件核對：實作及驗收

2026-09-11。這份報告對應新增的 live eligibility adapter，與先前模型自行比較房源的結果分開。完整實際驗收尚待凍結版本執行，目前不宣稱完成或整包品質通過。

## 已接入的資料路徑

使用者原話 → 私人持久狀態 → 模型提出候選網址 → host 獨立保存原頁 → 程式解析有限欄位與目前條件 → eligibility 核對 → 同一份 artifact 產生比較、排序及待辦。程式在發布、重開與匯出時重算；舊條件下的回答留作歷史。模型不能靠把候選改名、寫一段「例外」或修改自己的排序來越過正式比較。

這是受限的本機比較介面，不是已完成任意自然語言與任意房源網站的通用裁判。下載版包含離線工具及接入文件；其他 agent host 仍需明確連接，不會因為裝入 skill 就自動具有本機 UI 的控制器。

## Review 修正類別

- P1：實際 host source shape 與 engine 不合；過期呼叫未結束阻止後續研究；來源保存中斷卻顯示恢復成功。
- P1：後續預算誤刪暖氣／電梯要求；多戶頁面冒充單戶；至少運算或偏好強度誤套；未知條件無法在後續釐清。
- P2：偏好不符因待查項少而反被排前且缺點消失；問題／網址被誤當條件；選項題目被重複存成新要求。
- P2：切換對話時殘留前一段條件；限制不清的介面讓人期待任意知識問答。

原失敗測試與獨立 review 留在私人 study，修正後的通過不能回寫成原版沒有問題。

## 驗收方法及限制

先做離線行為／故障回歸，再按[固定計畫](plan.md)做最多兩次 Astra low 的真實網址比較。條件、來源和正式產物一致性、首句及整段體驗分開看；scripted 使用者輸入不是真人滿意度。模型原始 proposal 與 host 產生的可見回答分別保存，不能把程式文案的改善歸因為模型自身對話能力提升。

數字、使用版本、實際來源、token 用量及獨立評閱會在執行後追加；本段不預填成功。
