# 真實房源與條件核對：實作及驗收

2026-09-11。真實來源、目前條件、回答、候選排序與待辦已接上同一份程式核對產物。凍結版 `153335f` 完成兩次 Astra low 實際呼叫及一次真正的服務重啟；硬條件與恢復通過，但第二輪漏答暖氣追問，這個失敗保留。修正版 `9c17340` 已完成同資料重播、獨立復核、2,278 項完整回歸及本機安裝。這不是整包對話品質或正式上線的通過證明。

## 已接入的資料路徑

使用者原話 → 私人持久狀態 → 模型提出候選網址 → host 獨立保存原頁 → 程式解析有限欄位與目前條件 → eligibility 核對 → 同一份 artifact 產生比較、排序及待辦。程式在發布、重開與匯出時重算；舊條件下的回答留作歷史。模型不能靠把候選改名、寫一段「例外」或修改自己的排序來越過正式比較。

這是受限的本機比較介面，不是已完成任意自然語言與任意房源網站的通用裁判。下載版包含離線工具及接入文件；其他 agent host 仍需明確連接，不會因為裝入 skill 就自動具有本機 UI 的控制器。

## Review 修正類別

- P1：實際 host source shape 與 engine 不合；過期呼叫未結束阻止後續研究；來源保存中斷卻顯示恢復成功。
- P1：後續預算誤刪暖氣／電梯要求；多戶頁面冒充單戶；至少運算或偏好強度誤套；未知條件無法在後續釐清。
- P2：偏好不符因待查項少而反被排前且缺點消失；問題／網址被誤當條件；選項題目被重複存成新要求。
- P2：切換對話時殘留前一段條件；限制不清的介面讓人期待任意知識問答。

原失敗測試與獨立 review 留在私人 study，修正後的通過不能回寫成原版沒有問題。

## 驗收方法及限制

先做離線行為／故障回歸，再按[固定計畫](plan.md)做最多兩次 Astra low 的真實網址比較。條件、來源和正式產物一致性、首句及整段體驗分開看；scripted 使用者輸入不是真人滿意度。模型原始 proposal 與 host 產生的可見回答分別保存，不能把程式文案的改善歸因為模型自身對話能力提升。

## 修正版與交付檢查

修正版 `bounded-text/2` 把資訊追問另存為 `information_requests`，保留原句及所屬訊息；程式自行加入需要回答的欄位。`inquiries` 保存每間房源的答案／未知與來源；`information_todos` 只為尚在考慮的候選補上資訊工作。詢問「暖氣是否包含」不會變成「暖氣必須包含」，也不改排序。

使用原本兩輪的原話、proposal 和四份真實來源做**離線程式重播**，沒有重抓網頁，也沒有新增模型呼叫：

| 同一份資料下的差異 | v1 真實執行 | v2 程式重播 |
| --- | --- | --- |
| 條件、證據、核對結果與排序 | 已保存 | 兩輪皆與 v1 完全一致 |
| 第二輪暖氣追問 | 未回答 | 兩間都明示尚未確認 |
| 第二輪補充資訊待辦 | 缺漏 | 只為 B 查書面租金明細及供暖費說明 |
| 已排除 A | 不推薦、不查證 | 維持排除，未因資訊追問回到待辦 |
| 防改寫 | 共同 artifact 驗證 | 刪除資訊待辦、替換答案、改來源／追問來源都拒絕 |
| 文案 | 反覆逐條講來源相符，樓層用語重複 | 合併相符說明、去除 B 的重複未知資訊、保留面積「約」 |

第二輪會出現「暖氣費是否包含：尚無可核對的說明，目前未確認」，下一步包括「房源 B（補充資訊）：查找書面租金明細與供暖費說明，確認暖氣費是否包含」。這是程式依據原始實測資料生成的修正版例子，不是另一輪新模型回答。

新增的 host 回歸走完整兩輪提案、捕捉來源、接受、匯出和重新開啟流程，刻意讓 actor 漏選暖氣欄位，確認答覆／待辦仍保留。原始 v1 呼叫和失敗不覆寫。單憑字數也不能判斷改善：兩輪可見文字從 537／535 字元變為 482／572，第二輪因補回重要資訊而更長。

## 如何現在試用

開啟 [本機介面](http://127.0.0.1:8765/)，在「從你的需求開始」建立新對話，可以貼上最多三個想比較的房源網址，說明明確條件。開始後可補充或修改需求；「查看目前條件與待辦」和匯出的 current comparison 使用同一份核對結果。舊版實驗保持只讀，不把舊答案當作新版結果。

下載版使用 [live eligibility 接入文件](../../skills/vet-flat/references/live-eligibility.md)及 [CLI](../../skills/vet-flat/scripts/live_eligibility.py)。其工作仍在用戶本機，由用戶自己的 agent 與 host 執行；不需要新增遠端 worker。控制實驗呼叫上限的是本機 Lab，與租屋預算分開。

## 保留的限制及後續優先順序

1. P1 已修：本次支援的暖氣追問不再依賴 actor 自選欄位；未知答案和相應待辦都有程式核對。這不是對所有任意問句的完整覆蓋保證。
2. P2：正式比較仍有制式、重複的待查文字。首句有具體價差／排除理由，但尚不能以這兩輪證明「講人話」或長對話體驗通過。
3. P2：目前 live adapter 支援有限的明確中英文條件、最多三個候選和有限單戶廣告格式；未知需求會保留並阻止無條件通過。任意網站、複雜條件例外、移除舊候選和完整開放問答未完成。
4. P2：其他 agent host 必須明確接入離線 CLI 與當前狀態；安裝 skill 的文件指標本身不保證 host 每次執行核對。
5. P3：以已知網址／純條件變更繞過模型提案，再用固定來源與新的多輪情境比較品質與用量。
