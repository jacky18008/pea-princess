# 2026-09-11：恢復可測實際回答的本機平台

這輪交付是可運作的輸出測試台。正式產品仍是下載到使用者電腦的 skill／文件，由使用者自己的 agent 執行；沒有新增代管 worker、公開聊天產品或草稿功能。

## 修正的問題

先前畫面的「Codex」回答並不是完整的模型回覆：模型只能交出候選 URL 和重點欄位，host 再用固定模板產生比較文字。這適合測有限欄位的程式核對，卻無法驗收開放式討論、插問和語氣。暖氣問題在使用者貼出的舊場中也沒有得到回答。

新真人場明確使用 `output_mode: agent`。模型回傳的 `message` 和最多三組可選問題直接呈現，原始 JSON、完整對話、工具紀錄與用量保留；不再被比較模板取代。不呼叫 persona 扮演真人。舊 `checked` API 與核對工具仍保留，但不給新模式加上程式核對標章，`current_comparison` 為空。

另一個阻塞來自程式版本：Claude 同時修改主 repo，測試台即刻因來源指紋不同而停止。`tools/start_playground.py` 現在先保存固定版本，再啟動該份程式。後續主 repo 的編輯不會改變正在測的版本。舊場的兩次呼叫上限及來源指紋不被偷偷改寫；新版使用新場。

## 操作

在 repo 根目錄執行：

```sh
python3 tools/start_playground.py --port 8765
```

開啟 `http://127.0.0.1:8765/`，選「Agent 對話測試」、填需求、建立對話，按「研究並回覆」。之後在下方送出問題或修改條件；執行途中也能排隊插話。建立、閱讀、重整、匯出不呼叫模型。

啟動器印出快照及 manifest 路徑。快照保存 allowlist 內 Git 已追蹤檔案的目前內容，包含尚未提交的編輯，另明確帶入既有生成的 `dist/prompt-pack/INSTRUCTIONS.md`；未追蹤的新檔不會自動帶入。逐檔二次檢查來源未在複製期間變動，否則不啟動。它不會自動停止另一個正在運作的 server。

模型可讀固定版本的完整 skill 參考檔與腳本，並依目前 skill 規則研究開放公共資料。本次保留唯讀執行；不測原生 host 的檔案寫入與同 turn steering。房源正文可以直接貼入，host 不因模型重複了一個網址就擷取該刊登頁面。

## 實際三輪測試

模型 `gpt-6-astra`，CLI 明確設定 low；無自動 retry、無 Claude。這是控制端依使用者回報案例編寫的 regression replay，不是新蒐集的真人滿意度資料。房源數值來自先前保存的廣告文字，沒有重新取得或驗證在租狀態。

| 回合 | 測試輸入與觀察 | Processed tokens | 完成的工具操作 |
|---|---|---:|---:|
| 1 | £2300 房租上限、一房、安靜；比較提供的 A/B 文字。回答比較租金、房數、廣告面積與空間取捨 | 86,716 | 3 |
| 2 | 上限降至 £2100、臥室正對大馬路排除、追問暖氣。回答先說暖氣是否包含未知，再排除超額 A、保留 B 待查 | 57,918 | 1 |
| 3 | 問優先看哪間、要一句英文問仲介，不聯絡。回答接續 B 的條件，給出可用英文句子 | 25,285 | 0 |
| 合計 | 3 次回答，0 次 persona，0 次重試 | **169,919** | 4 |

第一輪開頭：

> 只看你保存的廣告，A 多花租金換較大空間，B 則較省錢；兩間標示的房租與房數都符合你的要求。

第二輪開頭：

> 目前不能確認暖氣費是否包含在房租內：你保存的兩間廣告文字都沒有這項資料，不能當作已包含，也不能斷定另收。

第三輪提供：

> Could you confirm whether the bedroom windows face a main road and whether heating is included in the £1,800 monthly rent?

每輪 raw receipt 的 `message/questions` 與保存的呈現內容逐字一致。瀏覽器實際送出三輪並看到結果；重新整理後仍顯示第三輪、`3/12` 次呼叫、無阻塞訊息，輸入框可用。此為測試完成時的狀態，使用者後續操作會繼續增加。

獨立 GPT-6 Astra evaluator 閱讀整段對話及收據，未找到這三輪的高／中嚴重度回答問題；低嚴重度為第一輪重複提醒廣告／EPC 未核實，以及面積差 41.52% 過度精細。沒有據此宣稱跨模型、完整研究或正式上線品質通過。
