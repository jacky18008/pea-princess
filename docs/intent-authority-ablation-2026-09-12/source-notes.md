# Official patterns informing the experiment

Reviewed 2026-09-12. These are design references, not evidence that a provider has solved this particular rental-assistant failure. The mappings below are our testable inferences. No framework dependency is added.

| Official source | Relevant guidance | Application and limit |
|---|---|---|
| [Google PAIR: Feedback + Control](https://pair.withgoogle.com/chapter/feedback-controls/) | Different meanings of feedback should not be conflated; ambiguous feedback should have limited impact, and preferences should remain editable. | A general “continue” should not silently promote every suggestion into a requirement. Preserve the scope of a user's correction. This is our application to conversation, not a claim that PAIR provides an intent parser. |
| [Microsoft HAX: Scope services when in doubt](https://www.microsoft.com/en-us/haxtoolkit/guideline/scope-services-when-in-doubt/) | When uncertain about the user's goal, disambiguate or narrow the service appropriately. | Clarify a consequential ambiguity while continuing independent work. This does not require repeated approval for an explicit change. |
| [OpenAI: Safety in building agents](https://developers.openai.com/api/docs/guides/agent-builder-safety) | Separate untrusted content from privileged instructions, constrain information passed between steps and evaluate traces. | Keep evidence, exact user messages and assistant suggestions distinct. A role-shaped object cannot itself authenticate who authored it. The experiment supplies roles through the trusted host, not extracted from a listing. |
| [OpenAI: Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs) | Schema adherence does not eliminate mistakes in the generated content. | A valid JSON requirement can still falsely attribute a decision to the user. C preserves raw statements instead of asking another model to manufacture authoritative normalized fields. Its schema is not a correctness certificate. |
| [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | Context is finite; retain important decisions and constraints through selective context management and external notes. | Test a compact role index rather than a growing general policy essay. This two-turn experiment does not establish that the helper solves long-context loss or compaction. |
| [OpenAI: Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) | Use task-specific evaluations, retained logs, representative cases and calibrated grading; model variability matters. | Freeze cases, preserve failures, review grader reasoning and repeat each condition. We use the repository's local durable CLI runner, not the hosted evaluation service described elsewhere on the page. |
| [Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | Agent evaluation needs traces/outcomes and consistency across nondeterministic attempts; “at least one success” differs from success on every attempt. | Report all three trials per cell, plus separate authority and useful-service gates. A successful retry cannot erase an earlier failure. Three trials cannot prove production reliability. |

The important separation is between **evidence**, **user authority** and **analyst judgment**. All three are useful. The proposed harness gives them distinct provenance without requiring the assistant to stop making recommendations. Enforcing a known numeric constraint remains the existing programmatic eligibility layer's job; deciding whether a sentence actually authorized that constraint remains a semantic problem evaluated here.
