# 使用者條件與 Agent 建議：三次重複實驗

2026-09-13（London）。分支：`codex/intent-authority-ablation-20260912`。

**小幅規則修改有值得繼續測的訊號，但還不能宣稱問題已修好。** 在較聚焦的對話測試中，三種版本都沒有出現會實際擴大／放寬本案例排除條件的錯誤；用語仍有漂移。額外加入原文索引的版本，則在第二次重複出現一次跨房源的來源混淆。單跑第一次會漏掉這次錯誤。

研究已完成；實驗變更留在分支，未合併到 main 或替換測試台。公開 skill 的實際改動很小：一段決策歸屬原則、修正「對話中的結論優先」的說法，以及選用的原文索引 helper。沒有加入一大篇一般性提醒，也沒有把每次改條件變成額外確認流程。

## 方法與適用範圍

原定工具版先完成 3 通就用了 947,069 processed tokens，無法在原先估計的成本內完成矩陣。因此在保持原始資料的前提下，另凍結較窄的 v2。完整原因與事前放行條件在 [版本修訂紀錄](amendment-v2.md)，原 [預登記計畫](plan.md) 沒有覆寫。

V2：**3 種改法 × 2 個情境 × 3 次獨立新對話 × 2 輪 = 36 通、18 段對話**。全部完成；沒有重試、未知用量、工具越界或公開檔案改寫。第二輪帶入該次模型真正的第一輪回答，而非固定的優良範本。順序事先固定並輪換；排序 seed 不代表模型輸出可重現。

模型為 `gpt-5.6-terra`，effort `low`，深度標籤 `standard`，CLI `0.153.4`。兩個案例都是明確標記的離線虛構資料：安靜偏好／大馬路臥室排除，以及獨立設計的地區／通勤／管理費條件例外。它們測條件理解，**不是真實房源研究、完整 standard 掃描、長上下文、重開接續或原生選項提交的驗收**。

各版本的 SKILL、rules、inputs、conversation-quality 四份檔案以原文直接提供。工具與額外檔案讀取不在這個測試範圍；控制器在觀察到工具事件後會停止後續呼叫，並非作業系統層的預防隔離。A 是現版規則「在共同 wrapper 下」的基準；直接把規則放在開場前，本身就改變了原本的讀檔流程。

## 結果：主門檻與用語問題分開看

「實質條件錯誤」是把偏好、建議或限定例外變成會改變本案例判斷的使用者限制；「用語漂移」則包括把目標叫底線、把特定窗向條件泛稱安靜硬條件，但在完整上下文中尚未改變實際排除結果。後者仍須修，**不能把主門檻通過說成完全沒有亂講條件**。

| 版本 | 實質條件錯誤／6 段 | 條件用語漂移（A1）／6 段 | 完整品質門檻／6 段 | 12 通 processed tokens |
|---|---:|---:|---:|---:|
| A 現版 | 0 | 4 | 6／6 | 200,450 |
| B 短版原則 | 0 | 2 | 6／6 | 203,038（比 A 多 1.3%） |
| C 加原文索引 | 0 | 1 | 5／6 | 207,178（比 A 多 3.4%） |

完整品質門檻同時要求條件、來源正確性、有效推進及互動負擔合格；開場另設獨立門檻。這是預先凍結的標準，不是事後為了選某個版本改分。用語漂移數是把原有 A1 評分另外展開，沒有改動原分。

| 版本／情境 | 三次完整門檻 | 條件用語漂移（A1） | 最差 A／E／Q | 最低 U／O |
|---|---:|---:|---:|---:|
| A 安靜／窗向 | 3／3 | 3／3 | 1／0／0 | 2／2 |
| A 地區／通勤／費用 | 3／3 | 1／3 | 1／1／0 | 2／2 |
| B 安靜／窗向 | 3／3 | 0／3 | 0／0／0 | 2／2 |

| C 地區／通勤／費用 | 2／3 | 0／3 | 0／2／0 | 2／2 |

每格取六個回合中的最差值：A 為條件歸屬、E 為事實錯誤、Q 為多餘互動負擔，越低越好；U 為有效推進、O 為開場品質，越高越好。A1 統計不包含 E1 的費用措辭問題。

B 對原來的安靜案例表達較乾淨，但在轉移情境仍有用語問題；不是全面改善的證明。每格只有三次，沒有統計等效、顯著優勢或跨模型可靠性的結論。

## 重複測試抓到的錯誤

C 的地區／通勤案例，第二次重複、第二輪說：

> 但資料一處說沒有固定管理費，另一處又列每月 £80、未說是否已含租金

「沒有另收固定管理費」其實屬於 A、B，**不屬於 C**。C 只有 £80 是否已含在 £2,090 內尚未確認的資料。模型仍保留 C 的條件式推薦，但捏造了一個來源矛盾。獨立評分為 E2，主 Agent 核對原始 fixture 與完整回答後同意。

這表明「保留使用者條件」與「正確歸屬房源事實」是不同問題。原文索引沒有解決後者。這一次錯誤也不足以證明索引造成幻覺；只能說 C 本輪未通過完整門檻，尚無理由把它當成預設可靠性修補。

仍保留的用語問題包括：

- 把「通勤希望 40 分鐘左右」叫做「通勤底線」，但仍推薦 46 分鐘的 A 作第二選擇。
- 把「臥室正對大馬路就排除」泛稱「安靜硬條件」。上下文仍指向窗向，沒有真的擴成所有噪音或鐵路排除。
- 把「超過 45 分鐘」改述成「45 分鐘以上」。本案例沒有恰好 45 分鐘的候選，故目前結果未變；這是下一組必須補的邊界。
- 把房租加固定管理費的小計叫作「每月總花費」。其他帳單未提供，說法容易讓人誤會費用已全部查清。

完整引文、來源對照與最小更正在 [獨立評閱紀錄](grader-review.md)。

## 開場與「講人話」

36 個第一句都獲獨立評閱 O2，36 輪皆 U2、Q0：有可用建議、能推進比較，沒有多餘確認門檻。V2 沒有另外一段進度訊息，因此第一個可見回答與最後回答的開場相同。這不代表已通過實際工具執行前的進度訊息體驗；v1 首句仍曾先講讀取流程。

例如 B 的第一個地區案例回覆開頭是：

> 我會先看榆庭公寓：它在你偏好的北區、月租 £1,980 沒超預算，47 平方公尺也是三間最大；代價是通勤 46 分鐘，比你的 40 分鐘目標多 6 分鐘，且要轉乘一次。

它給出判斷與代價，讓使用者有東西可以回應；沒有先列一串必填資料。A 也能給出好的開場，因此不能把這項結果全部歸功於 B 的新增文字。

## 評分流程的自我 review

獨立 GPT-6 Astra 先寫凍結 rubric／轉移案例及私人預期解讀。原設計 Agent 後來無法繼續接收任務，評閱改由新的 Astra 讀相同凍結資料完成；沒有改 rubric。它只看匿名的 18 段完整對話、原始使用者回合與資料，不看版本名稱、修改內容、排序或 token 成本。評分完成且 hash 保存後才解開對照。

主 Agent 隨後做了以下核對：

1. 核對兩個 fixture 與凍結 grader notes；檢閱每組第一次重複的完整回答，以及所有重大／邊界評分的引文和脈絡。
2. 同意 C 的來源混淆為 E2；它不是單純措辭，也不能因最後仍說「待確認」就抹掉捏造的來源。
3. 沒把「我建議不要選」自動判成未經授權排除，也沒把一句「安靜硬條件」脫離前後句放大成已排除所有噪音。這些仍以 A1 清楚列出，供使用者檢查。
4. 「現有資料下每月總花費是清楚的」保留為有爭議的 E1／E2 邊界：本輪只比較房租與固定費，上下文支持較窄解讀，但文字不宜沿用。沒有偷偷改成更好看的分數。
5. 以程式重算全部 18 段、六個三次重複分組、39 份模型用量收據；保留原分、缺席的 v1 slots 與版本差異。

評分凍結後，另請同一位獨立評閱 Agent 檢查未盲化報告；它從 39 份原始 stdout 重算用量並核對彙整。依其回饋補齊原 rubric 要求的每格最差分數，未更動原始評分。

這仍是 **AI 對合成案例的評估，不是人工真值或真實使用者滿意度**。腳本使用者的第二輪不能當真人正面回饋。轉移案例在本輪由獨立評估者設計，但現在已公開，之後只能當回歸案例，不能再稱新的 holdout。

## 用量與執行問題

| 範圍 | 實際通數 | Input | 其中 cached input | Output | Processed |
|---|---:|---:|---:|---:|---:|
| v1 工具版，停止的部分矩陣 | 3 | 931,849 | 809,216 | 15,220 | 947,069 |
| v2 聚焦版，完整矩陣 | 36 | 599,846 | 233,728 | 10,820 | 610,666 |
| 本輪測試模型合計 | **39** | **1,531,695** | **1,042,944** | **26,040** | **1,557,735** |

Processed = input + output；cached 已包含在 input 裡，不再加一次。39 通均有完整用量；原 200 萬測試模型預算剩 **442,265**。開發與 Astra 評閱 Agent 的用量不在此表內，不能稱這是整個任務所有用量，也不能用它換算訂閱扣額或金額。

v1 有 32 次不同的完成工具操作，其中 5 次命令失敗；沒有重試模型呼叫。第一通就有三次 reply_check，包含兩次失敗。v2 的 36 通沒有工具事件。由於工作範圍和完成樣本不同，不用 v1／v2 的每通平均差異宣稱無損省 token。

本次流程也有兩項具體教訓：

- **預估不能只看資料檔大小。** 必須估每個讀檔、計算、檢查回合再次處理上下文的成本。我原先低估了它，直到第三通已在執行才完成停用決策。
- **成本檢查應是可執行的停止點。** V2 已加入預設只派送一通的上限；首通 16,750，乘 36 為 603,000，符合剩餘額度後才釋出另外 35 通。首通沒有丟棄，仍算在矩陣中。這個檢查不看語意分數，也不挑好答案。

## 官方資料對設計的啟發

[Google PAIR](https://pair.withgoogle.com/chapter/feedback-controls/) 對模糊回饋的有限解讀，支持區分「繼續工作」與「同意所有曾提過的條件」這個設計方向。[OpenAI structured outputs 文件](https://developers.openai.com/api/docs/guides/structured-outputs) 提醒內容仍可能出錯；本輪 C 的來源混淆正說明角色／JSON／hash 不會自動證明語意正確。[Anthropic 的 eval 指南](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) 區分曾成功一次與每次都成功，這次第二次才出現的錯誤就是保留所有重複結果的理由。

這些是我們據以提出的假設與測試方法，不是宣稱供應商已解決本專案問題。完整官方來源與適用邊界在 [來源筆記](source-notes.md)。
